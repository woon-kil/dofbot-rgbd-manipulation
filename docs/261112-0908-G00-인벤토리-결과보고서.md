# G00 인벤토리 결과 보고서 (읽기 전용)

- 실행일: 2026-11-12. 플랜: `docs/261112-0902-G00-인벤토리-실행플랜.md` (advisor 검토 반영).
- **판정: `PARTIAL_READONLY`.** 읽기 전용 범위는 완료했으나 G00 `PASS`는 주장하지 않는다. ADR-001이 요구하는 대조표 중 `get_joint_state` 실제 반환 길이, 물리 서보별 움직임, FK 검증은 읽기 전용으로 얻을 수 없어 **G02로 이월**한다.
- **로봇 이동·쓰기·조회 API 호출 0건.** 실행한 명령 줄 전체를 `import|Arm_serial|Arm_Device|Arm_Lib(|smbus|i2cset/get/detect/dump`로 검사한 결과 일치 0건(아래 출력).
- 증거: `evidence/G00/manifest.json`(요약, 마스킹), 원문 로그 `evidence/G00/raw/*.log`(gitignore, 해시는 manifest). 스크립트 `scripts/g00_jetson_readonly.sh`, `scripts/g00_p620_readonly.sh`.

## 2. 카메라 내부 파라미터 (DaBai, 드라이버 `camera_info` 실측)
| 항목 | 컬러 (`dabai_color_optical_frame`) | 깊이 (`dabai_depth_optical_frame`) |
|---|---|---|
| 해상도 | 640×480 | 640×400 |
| fx, fy | 479.07, 478.98 | 305.88, 305.88 |
| cx, cy | 315.07, 237.41 | 320.53, 201.00 |
| 왜곡 모델 | rational_polynomial (d≈0.017, 0.004, 0.0003, 0.0005) | rational_polynomial (d 전부 0) |

**RGB-D 정합 여부:** 기본 런치는 `depth_registration=false`, `align_mode=HW` 파라미터가 존재한다. 컬러와 깊이의 해상도·내부 파라미터가 다르므로 **기본 설정은 정합 출력이 아니다.** 정합 확인은 G01. 드라이버가 알린 color→depth 정적 변환(이동 12.38, -0.03, 1.60 / 회전 거의 0)의 **단위는 미확인(UNVERIFIED)**이다.

## 3. SDK·URDF에서 읽은 사실 (G01.5 입력)
| 항목 | 값 | 출처 |
|---|---|---|
| 이동 명령 | `Arm_serial_servo_write6(s1..s6, time)`: `time`은 **운행 시간(주석 "time是运行的时间", ms 단위로 추정, 단위 확인은 G01.5)**. 속도 인자가 아니다 | `jetson-sdk.log` Arm_Lib.py:144-145 |
| 각도 범위 | s1~s4, s6: 0~180, s5: 0~270 (초과 시 거부 메시지) | 같은 파일 146-147 |
| 각도 변환 | s2, s3, s4는 `180 - 값` 반전. 펄스 매핑 0~180 → 900~3100, s5 0~270 → 380~3700 | 같은 파일 150-173 |
| 회독 | `Arm_serial_servo_read(id)` 1~6, 0~180 반환(s5는 0~270), 오류 시 None | 같은 파일 188-213 |
| 토크 | `Arm_serial_set_torque(onoff)` 함수가 존재한다. 호출하지 않았고 토크 해제 상태 회독 가능 여부는 **UNVERIFIED** | 같은 파일 270 |
| 정지 API | `def` 목록에 **정지/비상정지 함수가 없다**(리셋·토크·PWM 등만). 하드웨어 정지 수단은 전원 스위치로 가정(미확인) | `jetson-sdk.log` def 목록 |
| URDF 관절 한계 | Arm1~Arm4: ±1.5708 rad, Arm5: -1.5708~3.1416 rad, grip_joint: -1.6~0 rad, effort 100, velocity 1 | `jetson-urdf.log` |
| URDF 한계와 SDK 범위 | URDF ±90°(총 180°)와 SDK 0~180, URDF Arm5 -90~180°(총 270°)와 SDK 0~270은 **폭이 일치**한다. 영점 오프셋 대응은 미검증(G02) | 위 두 로그 |
| **DaBai 장착 링크** | URDF에서 `DaBai_DCW2_Link`는 **`Arm4_Link`의 고정 자식**이다. 손목 회전 `Arm5_Joint`와 그리퍼는 그 아래에 있다 | `jetson-urdf.log` 319-328 |
| 그리퍼 TCP 후보 | `Gripping_point_Link` (`Arm5_Link` 자식, 고정) | `jetson-urdf.log` 773-782 |

**설계 영향:** URDF대로면 카메라는 손목 회전(Arm5)과 함께 돌지 않으므로 hand-eye의 기준 링크는 `Arm5`가 아니라 `Arm4_Link`이고 그리퍼 TCP와 카메라는 `Arm5` 각도만큼 상대 자세가 바뀐다. 이는 URDF 문서 값이며 실물 장착 확인 전까지 UNVERIFIED이고, ADR-001이 경고한 "`Arm4_Link` FK를 실제 tool frame으로 가정하지 말 것"과 직결된다.

## 4. G02로 이월하는 항목 (읽기 전용으로 얻을 수 없음)
1. `get_joint_state`(또는 `Arm_serial_servo_read`) 실제 반환 길이와 순서
2. 물리 서보별 움직임과 URDF 관절의 대응, 영점 오프셋
3. FK 검증(FK 오차 측정 방식은 ground truth 정의 필요, 진단 P1-1)
4. 토크 해제 상태 회독 가능 여부(ADR-005 열린 질문)
5. `time` 단위 확정, 안전 상한 수치(G01.5)

## 5. UNVERIFIED로 남은 항목
Gemini 펌웨어와 SDK 버전(컨테이너 안 조회, G01), Gemini 깊이 스트림 해상도·시차 탐색 폭, color→depth 변환 단위, DaBai 최소 유효 거리·정확도, URDF와 실물 장착 일치, 하드웨어 비상 정지 수단.

## 6. 이슈·위험 기록
- 첫 DaBai 기동에서 컬러 `camera_info`가 20초 안에 나오지 않았다(깊이는 성공). 컬러 이미지 토픽을 구독한 상태에서 다시 시도해 성공했다(두 번째 실행의 로그가 `jetson-dabai.log`에 남고 첫 실행 로그는 덮어써졌다). 컬러 `camera_info`가 구독자가 있을 때 발행되는지는 추정이며 검증하지 않았다.
- `ros2 topic hz`는 `--no-daemon`을 받지 않아 오류가 났다(조회 실패, 영향 없음).
- Jetson 디스크 사용률 88%(여유 8.6 GB). G01 영상 수집 전에 저장 위치와 용량을 정해야 한다.
- DaBai 드라이버를 두 번 기동·종료했고 각각 종료 후 프로세스 없음을 확인했다. 팔 제어·카메라 구독 프로세스는 사전 점검에서 없었다(OLED 표시 서비스만 실행).

## 7. 다음 Gate 진행 가능 여부
- **G01(카메라 취득·Gemini 시야): 진행 가능.** 단 Gemini 펌웨어·깊이 모드 조회와 DaBai 정합 설정을 G01 증거 항목(깊이 스트림 해상도, 시차 탐색 폭, 정합 모드, 작업영역 유효율)으로 수행한다. 영상 저장은 개인 공간 사진이므로 `evidence/**` 원본 이미지는 gitignore 대상이다.
- G01.5, G02는 G01 이후. 안전 상한 수치는 이번 조사로 `time` 파라미터와 관절 범위 근거를 확보했으나 수치 자체는 사용자 결정이 필요하다.
