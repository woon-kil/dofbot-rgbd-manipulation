# G07 P3-0 블록 윗면 마커 가시성 확인(사진) 승인 요청 문서 — 설계 승인·도구 구현 단계 (P1·P2·P4 승인됨, P3·R10 미결) (팔 이동 없음, 2026-11-16)

**이 문서는 승인 요청 초안이다. 승인 칸이 모두 비어 있고, 사용자가 적기 전에는 도구 구현도 하드웨어 명령도 하지 않는다.** 근거: `docs/gates/G07-파지-판정과-들어올림-설계-초안.md` §2·§4(J1~J4 승인 2026-11-16). 선례: `docs/gates/G07-P2h-블록-지지-닫기-승인-요청-문서.md`. 이 시험은 **팔 관절 1~5를 명령하지 않으므로 새 높이 임계값(F4)이 필요 없다.**

## 0. 먼저 읽을 것
1. **푸는 질문:** (Q1) 손가락에 물린 위치에 있는 블록의 윗면 마커를 DaBai가 실제로 볼 수 있는가(예측: 못 본다, 영상 밖 약 51 px, UNVERIFIED)? (Q2) 블록을 손가락 축 방향으로 얼마나 물려야(h mm) 마커 중심·전체가 보이는가(예측: 중심 약 19 mm, 전체 약 43~50 mm)? 이 답이 들어올림 높이 후보(약 50 mm급)의 근거가 된다.
2. **이 시험이 답하지 않는 것:** 실제 팔 들어올림 중 거동, 파지력, 마커 PnP 이동량 정확도(이 거리), 낙하 위험.
3. **핵심 제안 — J6를 한 번도 움직이지 않는 안(안 A)을 권장한다.** 마커의 영상 위치는 블록의 위치로 정해지고 손가락이 열렸는지 닫혔는지로 정해지지 않는다(블록을 홀더가 손가락 사이에 놓고 있으므로). 따라서 **블록을 열린 손가락 사이 파지 위치에 홀더로 놓고 사진만 찍으면 Q1·Q2에 답할 수 있고, 서보 명령·정체 누름·발열 위험이 0이다.** 닫은 상태 비교(안 B)는 안 A 결과가 모호할 때만 별도 승인으로 요청한다. 단 이는 J2 문구(그리퍼만 닫은 상태)에서 한 걸음 더 보수적으로 바꾼 것이므로 사용자 결정(P1)이다.

## 2. 범위와 절차 (안 A, 제안)
| 항목 | 내용 |

## 3. 판정 기준(사전 등록 제안)
| 항목 | 기준 | 의미 |
|---|---|---|
| Q1 | h=0에서 마커 4개 모서리 모두 영상 안이면 **예측 반증**(기하·가정 재검토), 일부만 보이거나 전혀 안 보이면 예측과 일치 | 파지 자세 재관측 가능성 |
| Q2 | 마커 4개 모서리가 모두 검출되는 최소 h를 구한다 | 들어올림 높이 하한 |
| 예측 일치 | 보이는 h에서 마커 중심 픽셀이 예측과 행 ±20 px, 열 ±20 px 안 | 기하 가정(축 평행, TCP 오프셋) 지지 |
| 불일치 | 위 밖이면 가정(축 평행·오프셋·마커 위치)을 재검토하고 높이 후보를 확정하지 않는다 | 오프셋 오차(S4-13 UNVERIFIED) 신호 |
- 한계: h=0에서 마커가 영상 밖이면 위치 정보는 "안 보임"뿐이라 예측 행(532 등)과 직접 비교할 수 없다. 정량 비교는 h≥19(중심 가시)부터 가능하다.
- 카메라 최소 거리(DaBai 색상 초점·근접 한계)는 미확인이라 z≈86~96 mm에서 영상이 흐릴 수 있다. 흐리면 그 사실을 기록한다.

## 4. 중단 조건과 안전
- 홀더·블록이 카메라·손가락·팔을 건드리거나 블록이 떨어지면 중단, 사용자 중단. 서보 명령이 없으므로 중단 때 추가 동작이 없다. 정지는 전원 스위치(SDK 정지 API 없음).
- **프로젝트 규칙:** 블록 배치·이동 안내는 **SVG로 제안**한다(손이 놓는 자리 = 카메라 사진 위, 검증 완료 후에만 사용자 확인 요청). 아래 §5.
- 개인 사진·원본은 `data/` 또는 gitignore된 증거 폴더에 둔다.

## 5. 구현 필요 (승인 뒤)
- 캡처 스크립트: `scripts/g01_dabai.sh`·`g01_dabai_probe.py` 패턴(Jetson에서 드라이버 기동 → 컬러 저장 → 종료)에 h 라벨과 마커 검출(기존 PnP·모서리 검출 코드 재사용 여부는 구현 전 확인)을 붙인다. **로봇 명령 코드를 포함하지 않는다**(서보 어댑터 import 없음). 가짜 영상으로 검출·판정 시험, 스냅샷, 래퍼, 사용 전 advisor.
