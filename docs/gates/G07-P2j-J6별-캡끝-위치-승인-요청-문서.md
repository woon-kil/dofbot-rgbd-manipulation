**승인 칸은 모두 비어 있다. 사용자가 적기 전에는 구현도 하드웨어 명령도 하지 않는다.** 근거: `docs/gates/G07-파지-접근-설계-초안-팁모델-정정.md` §0-1·부록 A(S4-13 열림 대 R14~R16 오므림 모순, J6 상태 가설), 사용자 승인(G-0, 2026-11-16 "권장안으로 진행"). 기존 도구 재사용: P2g(`scripts/g01_p2g_gripper_test.py`, 문서 `docs/gates/G07-P2g-그리퍼-단독-승인-요청-문서.md`, 결과 §10).

## 0. 풀 질문 (이것만)
**그리퍼 J6 상태에 따라 캡 끝(손끝)의 손가락 축 방향 위치가 얼마나 달라지는가?** 상태: 열림 약 100(S4-13 기준 98), 파지 약 140(블록 30 mm 간격에 해당하는 J6 약 129~141), 오므림 178(R12~R16). 이 값으로 상태별 `tip_y`(팁 기하)와 파지·닫기 설계의 오프셋을 정한다.

## 2. 측정(제안, advisor 검토 반영)
- **잴 점 두 개:** (가) **캡 끝면 가운데 점**(S4-13과 직접 비교), (나) **둥근 끝의 맨 위 점**(K1에서는 손끝이 위를 향해 이것이 기울인 자세의 최저점에 해당, "끝면의 단단한 점 대 둥근 끝의 최저점" 정의 차이를 가린다). 두 점의 J6별 축 방향 높이를 같은 사진에서 잰다.
- **기준:** J6와 무관한 강체 표시(사용자가 Arm5 몸체에 붙인 스티커)와 쇠자(눈금 mm)를 **손가락과 같은 깊이**에 둔다. 폰은 **arm5 z축 방향**(열림 축 x와 손가락 축 y에 모두 수직)에서 보게 놓아 손가락이 벌어지거나 닫혀도 두 손가락이 같은 평면에 있어 가려짐·시차가 생기지 않게 한다. 점마다 사진 1장(점 사이 이동 중에는 찍지 않음).
- **140의 두 번:** P2g에서 닫는 쪽이 3~14° 뒤처졌다. 140은 열 때와 닫을 때 두 번 지나가므로 **둘 다 재고, 닫는 쪽 값을 파지 상태로 사전에 정한다.**
- 캘리퍼 간격은 이번 시험에서 기록하지 않는다. 시작·복귀 J6 회독(P2g에서 178 → 177 잔차)을 기록한다. 사진은 `data/`에만 두고 커밋하지 않는다.
- **배치 안내는 사진 위 SVG(역산 검증)로, 시험 녹화(영상 모드)로 눈금·손끝·초점을 먼저 확인한다**(R-P2j 전).

## 3. 판정(사전 등록, 결과 보기 전 고정 — 값을 얻는 시험)
- **판별력(mm로 계산):** 사진 판독 ±1~2 mm 대 아래 예측 사이 간격 7~20 mm라 서로 구분된다.
- **1차 산출:** J6별(178, 160, 140 닫는·여는 쪽, 120, 100) 점 (가)·(나)의 축 방향 위치 곡선과 불확도. 178 대 100의 Δ를 보고한다.
- **예측 네 개와 대조(사전):** P0: Δ ≤ 3 mm(J6 상태 무관), P1: Δ ≈ 7.5 mm(URDF 피벗 이동, 선형 대응 가정), P2: Δ ≈ 9~18 mm(열림·오므림 d 차이를 축으로 환산), P3: Δ ≈ 28 mm(S4-13 열림 대 R14 오므림). 어느 예측에 가장 가까운지와 (가) 대 (나) 차이를 기록한다.
- 이 값으로 상태별 `tip_y`(G-2)를 정한다. 140 닫는 쪽 값이 파지 상태 팁 위치다.
- **한계:** K1에서는 손가락이 위를 향하고 파지에서는 아래를 향해 링크 백래시 방향이 반대다(작겠지만 남김).

## 4. 중단 조건·안전(P2g와 같음)
J6 회독이 창 밖이거나 도착 실패 2회, 발열·소리·떨림, 사용자 중단이면 중단하고 승인된 복귀 1회(4800 ms)만 한다. 이 시험은 팔 이동이 없어 충돌·낙하 위험이 없다(J6 발열만 관리: 점마다 손 제거 확인, 종료 시 J6 발열 확인).

## 6. 도구 구현 결과 (2026-11-16, 하드웨어 없음, advisor 검토 반영)
**P2g 대비 실제 변경 목록(P2j-3 승인 범위 "점 목록·측정 입력 문구만"을 넘는 항목은 ★, 사용자 확인 칸 P2j-4):**
1. 점 목록 `[S,160,140,120,100,120,140,160,S]`(쓰기 8회, 승인 시간·창 동일).
2. 캘리퍼 입력을 폰 사진 번호 입력으로 교체. **§2의 캘리퍼 기록은 이번 시험에서 하지 않는다(도구에서 제거, 문서 §2의 "선택" 문구 삭제).**
3. ★ 모든 질문 앞 입력 버퍼 비우기(`flush_stdin`, R16 사고 수정과 같은 방식) — 자유 입력(사진 번호)과 y/N이 번갈아 나와 한 칸씩 밀리는 것을 막기 위함.
4. ★ 각 사진 기록에 epoch 시각 추가(폰 사진 EXIF 시각으로 사진 ↔ J6 점 대응을 독립 확인).
5. 사전 확인 4·5번(배치·시험 녹화), 이동 질문을 "손을 뗐고 폰·쇠자·스티커는 **열림 범위 밖 고정 자리**에 그대로 있습니까?"로 변경. 승인 문구 `APPROVE P2J REAL`.
6. **제거된 보호 장치:** P2g의 "간격이 예상 방향과 반대로 변하면 중단"(`REVERSE_TOL`, 캘리퍼 의존)이 이 시험에는 없다. **남은 보호: 회독 도착 검사(허용 3°)·창 [95,179]·승인 시간·쓰기 한도·정지 중 재전송 질문.** 쓰기·어댑터·창·시간은 P2g와 같다. `parse_caliper`·`GAP_SPREAD_OK`·`REVERSE_TOL`은 호출되지 않는 잔재로 남아 있다.

**쇠자·스티커 위치 제약(advisor 지적 1, R-P2j 전 해소):** 폰이 arm5 z축 방향에서 보고 손가락은 x 방향으로 벌어지므로, 같은 깊이에 둔 쇠자·스티커는 **열림 방향 위**에 놓여 간섭할 수 있다. J6 100에서 안쪽 간격은 44 mm지만 바깥 폭·링크 피벗은 더 넓다(URDF 피벗 간격 85 mm는 grip 0 기준, 실제 J6 100 외곽은 **미측정**). 쇠자·스티커는 **점마다 치우지 않고 열림 범위 밖에 고정**한다. 외곽을 정하려면 사용자에게 **J6 100 최대 열림에서 바깥 폭 측정**(P2g의 J6 100 사진·기록이 있으면 대체)을 요청하고, SVG는 179→100 전 구간 외곽을 반영한다.

**검증(실제 실행):**
- 가짜 서보 `--fake --fake-speed 20`: `ended=completed`, 쓰기 8회, 사진 9개(모두 epoch 있음). `--fake --fake-dry`: `dry_run completed`, 어댑터 기록 8건이 모두 `dry_run`(실제 쓰기 0).
- `--fake-speed 50`에서는 정착 감지가 빨라 가짜 서보가 미이동으로 처리돼 중단됨(P2g로는 확인하지 않음, 실기기와 무관한 가짜 도구 특성으로 추정).
- 스냅샷 `evidence/scripts_snapshot/261116-p2j`(MANIFEST sha256), 래퍼 `--check` 통과. **실제 Jetson dry run은 아직 하지 않았다**(사용자 TTY 필요).

**R-P2j 이전 순서(변경 없이 고정):** ① 바깥 폭 측정 요청 → ② 사진 위 SVG 배치(역산 검증) → ③ 시험 녹화로 프레임 확인 → ④ 사용자 TTY dry run(advisor 후 안내) → ⑤ R-P2j 승인 요청(advisor 후).
