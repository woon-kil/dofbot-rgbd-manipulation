# 큰 이동 M3 실행 안내: 실행 전 점검 묶음 → dry run (2026-11-15, 2판)

> **⚠ 무효 경고(2026-11-15 11:5x, 세션 A):** 이 문서의 자세 선정·가시성·구간 분포 서술은 쌍 선정 코드의 가시성 필터 버그(주석에 묻힌 `ok &= o`) 위에서 나온 것이라 **무효**다. `--real` 실행은 안전했지만 마커가 6회 중 6회 검출되지 않아 측정이 성립하지 않았다. 원인·재계산 결과(깊이 ≥ 148 mm에서 가시성 자세 26개, 최대 tip 거리 21.1 mm, 50~100 mm급 쌍 0개)·교훈: `docs/261115-1153-큰이동M3-가시성필터-버그-이슈보고서.md`.


**이 안내는 `--real`이 아니다.** 아래 두 명령 모두 팔에 쓰기 명령을 보내지 않는다(서보 읽기·카메라 촬영만). `--real`은 이 단계의 결과를 본 뒤 별도로 요청한다(승인 요청 문서 §5 결정 7). 근거: `docs/gates/G07-큰이동-M3-승인-요청-문서.md`, 스크립트 스냅샷 `evidence/scripts_snapshot/261115-bigm3/`(MANIFEST 16개 파일 + `MANIFEST-src.sha256` 19개 파일(충돌 검증 코드·자세 파일·URDF·메시), sha256 `42cb0307…7f8da774`).

## 1단계: 실행 전 점검 묶음 (읽기·촬영만, 약 2~3분)
```
bash scripts/p1_m3_precheck.sh
```
순서와 하는 일(이 순서가 중요하다: 프로세스 확인이 Jetson 읽기보다 먼저):
1. **래퍼 `--check`:** 필요한 파일 존재, `gripper_adapter.py` 두 사본 동일, Jetson에서 `Arm_Lib` import 가능(생성자 미호출), 팔 제어 프로세스 없음.
2. **Gemini 사진 1장:** p620 docker로 약 40초(로봇 명령 없음) → `data/g04/m3_<시각>.png`.
3. **출발 전 공통 점검:** 팔 제어 프로세스 재확인 → Jetson에서 서보 1~6 읽기, **Jetson `Arm_Lib` 소스 sha256**, **원시 서보 값 표본(J1~J4 각 20회)** → 사진 판정 → 스크립트 16개 sha256 판정, **충돌 검증 코드·자세 파일·URDF·메시 19개 sha256 판정(`src_sha256`)**.

**성공:** 마지막에 `출발 전 공통 점검: 통과`, `전체 통과. 다음(터미널에서 직접): bash scripts/g01_5b4_s42_run.sh --set 14`가 나온다. 중간 출력에서 볼 것:
- `[통과] readback_vs_K1`(J1~J4 ±2°, J5·J6 ±1° 안), `[통과] scene`(`block_move_in_scene_px` ≤ 4: 블록이 장면 안에서 확정 자리에서 3 mm 넘게 움직이지 않음. `camera_shift_px`는 기록만이라 0.5 px를 넘어도 통과할 수 있다), `[통과] scripts_sha256 {'n': 16, 'mismatch': []…}`, `[통과] arm_lib_version`(Jetson의 읽기 함수 `Arm_serial_servo_read`가 읽은 소스와 같다는 뜻; 파일 전체 sha와 설치 경로는 기록만).
- `[기록(정상)] raw_samples [(관절, 원시 SD(°), 일치율), …]`: 원시 값 퍼짐이 정수 반올림 흔들림(SD 0.289°)보다 작다는 뜻. `[기록(주의, 이동 판단에는 쓰지 않음)]`이 나오면 팔은 문제없지만 **원시 값 기반 예측의 효과를 다시 평가해야 하니 숫자를 알려 달라.**

**실패와 조치(모두 팔 이동 없음, 이후 단계는 실행되지 않음):**
| 메시지 | 뜻 | 조치 |
|---|---|---|
| `팔 제어 관련 프로세스가 실행 중이다`(종료 4) | 다른 제어 프로그램이 떠 있음 | 그 프로그램을 끄고 다시 실행 |
| `Jetson에서 Arm_Lib import 확인 실패`(종료 3, 1/3 단계) | Jetson 접속 또는 라이브러리 | 메시지 전문을 알려 달라 |
| `Jetson 읽기 실패` 또는 `Jetson 출력 해석 실패`(종료 3, 3/3 단계) | 서보 읽기·출력 해석 | 메시지 전문을 알려 달라 |
| `p620 접속 또는 프로브 파일 확인 실패`·`USB 사용 중` | 사진 단계 | p620 전원, Gemini를 쓰는 다른 프로세스 확인 후 재실행 |
| `[실패] readback_vs_K1` | 표에 어긋난 관절이 나옴. J6가 179에서 벗어났으면 오므림이 풀린 것 | **손대지 말고** 알려 달라 |
| `[실패] scene` | `block_move_in_scene_px`>4(블록이 장면 안에서 약 3 mm 넘게 이동) 또는 `phase_response`<0.5(전체 이동 추정 불안정: 조명·시야 변화) | 블록 위치와 조명을 확인하고 처음부터 다시 |
| `[실패] scripts_sha256` | `mismatch` 파일 이름이 나옴. 스크립트가 승인 때와 다름 | dry run으로 가지 말고 알려 달라 |
| `[실패] arm_lib_version` + `status: mismatch` | 설치된 읽기 함수가 읽은 소스와 다름 | **통과로 치지 않는다.** 해시 두 값과 저장된 `data/refs/jetson-Arm_serial_servo_read-*.py`를 알려 달라(원시 환산 가정을 다시 확인한다) |
| `[실패] arm_lib_version` + `status: unverifiable` | 설치 형태 때문에 함수 소스를 못 읽음(예: zip egg) | **통과로 치지 않는다.** `note`의 사유를 알려 달라. 회독·원시 표본은 같이 출력되니 함께 알려 달라 |

**롤백(팔 복구 아님, 만든 파일만):** 실패해도 스크립트가 종료 때 출력하는 `rm data/g04/m3_<시각>.png; ssh p620 'rm -rf ~/dofbot-g01-work/m3_<시각>'; rm evidence/G06/p1_preflight_*.json`.

## 2단계: dry run (읽기만, 쓰기 0회, **직접 연 터미널**에서)
1단계가 모두 통과한 뒤에만.
```
bash scripts/g01_5b4_s42_run.sh --set 14
```
- 하는 일: 현재 서보 값으로 이동 계획 세트 14를 만들고(높이 게이트·`p1_plan_check.py` 충돌 검증 통과 필수), Jetson에 보내 **쓰기 없이** 이동 목록·안전 질문을 끝까지 진행한다. 대화형이라 직접 연 터미널에서만 된다.
- **dry run이 하지 않는 것:** 촬영·DaBai 드라이버·원시 값 읽기(`capture()`)는 `--real`에서만 돈다. 원시 읽기 경로는 1단계 점검의 표본 읽기로 확인한다(`capture()` 안의 기록 코드는 가짜 시험으로만 확인됨).
- 화면에서 볼 것: `현재 회독(J1~J6): 89,91,…`, `집합 14 … 이동 27회(접기 8 + 자세 19)`, `게이트 통과`, 충돌 검증 최소 여유 **오프라인 기대값 블록 39.1 / 종이 69.0 / 베이스 46.9 mm**(실제 회독에 따라 조금 달라질 수 있고, 기준은 20 mm 이상), 안전 질문 7개(6번이 J2·J3·J4와 **오므린 그리퍼 서보 J6** 발열 확인). 모두 확인되면 **y**. 이후 `[이동 n/27]`이 표시되지만 서보는 움직이지 않는다.
- **성공:** `기록 확인: mode= dry_run ended= completed …`, `저장: evidence/G01/raw/g01_5b4_s4214_result-dry_run-<시각>.json`.
- 실패: `이동 계획 게이트 실패. 중단(팔은 움직이지 않았다)`(종료 8) → 화면의 `게이트 실패:` 줄 또는 `P1 블록·종이·베이스 여유 검증 실패`를 알려 달라. 안전 질문에서 **n** 또는 Ctrl-C는 쓰기 없이 중단된다.

## 3단계(별도 승인 뒤): `--real`
**실행 직전 순서(모두 같은 날, 이 순서):** `bash scripts/p1_m3_precheck.sh` → `bash scripts/g01_5b4_s42_run.sh --set 14`(dry run) → (R1 승인 뒤) `--real`. dry run 화면에서 `전체 최소 … 기준 20.0 → 통과`의 **20.0**과 이동 수를 확인한다(`P1_GATE_MM` 환경변수가 바뀌면 기준이 달라진다).
승인 요청 문서 §6의 R1에 사용자 승인이 기록된 뒤에만. 명령은 승인 후 별도로 안내한다(`*.sh` 안내 직전 advisor 검증).

## 끝나면 알려 줄 것
- 1단계와 2단계의 통과 여부와 마지막 몇 줄(실패 시 메시지 전체), 그리고 `raw_samples` 줄. 저는 dry run 기록 JSON에서 **쓰기 0회**, 세트 14, 이동 27회, 안전 질문 경로를 직접 확인한다.
- 모두 통과하면 `--real` 승인을 별도로 요청드린다.
