## 1단계: 실행 전 점검 묶음 (읽기·촬영만, 약 2~3분)
```
bash scripts/p1_near_precheck.sh
```
순서: ① 래퍼 `--check`(프로세스 확인 포함) → ② Gemini 사진 1장 → ③ 출발 전 공통 점검. **성공:** `출발 전 공통 점검: 통과`와 `전체 통과. 다음(터미널에서 직접): bash scripts/g01_5b4_s42_run.sh --set 15`. 중간에 볼 것:
- `[통과] readback_vs_K1`, `[통과] scene`(`block_move_in_scene_px` ≤ 4), `[통과] scripts_sha256 {'n': 17, …}`, `[통과] src_sha256 {'n': 22, …}`, `[통과] arm_lib_version`.
- **`[통과] marker_projection [('S', 48.9, …), ('E5', 60.7, …), ('E10', 83.7, …), ('E15', 94.8, …)]`**: 각 자세에서 마커가 영상 안에 들어오는 여유(px, 기준 ≥ 47)다. 이번 신규 게이트이며 FK로 직접 투영한 값이라 숫자가 위와 같아야 한다.
- `[기록(정상)] raw_samples`: 원시 값 퍼짐이 정수 반올림 흔들림보다 작다는 뜻. `[기록(주의 …)]`이면 팔은 문제없지만 숫자를 알려 달라.

**실패와 조치(모두 팔 이동 없음):** `팔 제어 관련 프로세스가 실행 중이다`(종료 4) → 그 프로그램을 끄고 재실행. `Jetson에서 Arm_Lib import 확인 실패`/`Jetson 읽기 실패`(종료 3) → 메시지 전문. `p620 …`·`USB 사용 중` → p620 전원·Gemini 점유 확인. `[실패] readback_vs_K1` → **손대지 말고** 알려 달라(J6가 179에서 벗어났으면 오므림이 풀린 것). `[실패] scene` → 블록·조명 확인 후 재실행. `[실패] scripts_sha256`/`src_sha256` → `mismatch` 파일 이름을 알려 달라(승인 때와 다름, dry run으로 가지 않는다). **`[실패] marker_projection`** → 어느 자세가 몇 px인지 알려 달라(마커가 시야 밖일 수 있다는 뜻이므로 실행하지 않는다). `[실패] arm_lib_version`(mismatch/unverifiable) → 통과로 치지 않는다. 사진 폴더 롤백은 종료 때 출력되는 줄을 쓴다(점검 기록 JSON은 증거라 지우지 않는다).

## 2단계: dry run (읽기만, 쓰기 0회, **직접 연 터미널**에서)
1단계가 모두 통과한 뒤에만.
```
bash scripts/g01_5b4_s42_run.sh --set 15
```
화면에서 확인할 것:
- `집합 15 … 이동 16회` 또는 `이동 17회`(시작 회독에 따라 다르다: 시작 (89,92,92,91)이면 16, J2=91이거나 **J3=93·J4=92(11:20 점검 때 회독)이면 17**). **다른 숫자이면 n.** 시작 회독이 K1과 J3 2° 차이(허용 경계)여도 계획은 정상 생성된다(오프라인 확인: 충돌 검증 최소 블록 32.3·종이 60.7·베이스 39.7 mm, 가짜 시험 completed).
- `게이트 통과`, 충돌 검증 `전체 최소 … 기준 20.0 → 통과`(**20.0** 확인, 환경변수 `P1_GATE_MM`이 바뀌면 기준이 달라진다), 최소 여유 **블록 약 32, 종이 약 61, 베이스 약 40 mm**.
- 안전 질문 7개(6번은 J2·J3·J4와 오므린 그리퍼 서보 J6 발열 확인) → 모두 확인되면 **y**. 이후 `[이동 n/16]`(또는 17)이 표시되지만 서보는 움직이지 않는다.
- **성공:** `기록 확인: mode= dry_run ended= completed …`. dry run은 촬영·DaBai·원시 읽기(`capture()`)를 하지 않는다.

## 3단계(별도 승인 뒤): `--real`
승인 요청 문서 §5의 R2에 사용자 승인이 기록된 뒤에만. 명령은 승인 후 별도로 안내한다(`*.sh` 안내 직전 advisor 검증). 실행 직전 순서: 점검 묶음 → dry run → `--real`(모두 같은 날, 블록·카메라·받침·팔을 만지거나 30분 넘게 지나면 점검부터 다시).

## 끝나면 알려 줄 것
1·2단계의 통과 여부와 마지막 몇 줄(실패 시 메시지 전문), `marker_projection` 줄과 `raw_samples` 줄. 저는 dry run 기록 JSON에서 쓰기 0회와 이동 수를 직접 확인한다.
