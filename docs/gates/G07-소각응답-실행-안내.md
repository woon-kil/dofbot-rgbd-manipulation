## 1단계: 실행 전 점검 묶음 (읽기·사진 1장만, 약 2~3분)
```
bash scripts/p1_step_precheck.sh
```
순서: ① 래퍼 `--check`(프로세스 확인 포함) → ② Gemini 사진 1장(블록 위치 확인용) → ③ 출발 전 공통 점검. **성공:** `출발 전 공통 점검: 통과`와 `전체 통과. 다음(터미널에서 직접): bash scripts/g01_5b4_s42_run.sh --set 16`. 이번에는 카메라 시험이 아니라 `marker_projection` 줄이 없다. 볼 것: `[통과] readback_vs_K1`, `[통과] scene`, `[통과] scripts_sha256 {'n': 17, …}`, `[통과] src_sha256 {'n': 20, …}`, `[통과] arm_lib_version`, `[기록(정상)] raw_samples`.
**실패와 조치(모두 팔 이동 없음):** 이전 안내와 같다 — `팔 제어 관련 프로세스가 실행 중이다`(종료 4) → 앱 종료, `Jetson … 실패`(종료 3) → 메시지 전문, `[실패] readback_vs_K1`(J6가 179에서 벗어나면 손대지 말고 알림), `[실패] scene`(블록·조명 확인), `[실패] scripts_sha256`/`src_sha256`(mismatch 파일 이름을 알림), `[실패] arm_lib_version`. 사진 롤백 줄은 종료 때 출력된다(점검 기록 JSON은 증거라 지우지 않는다).

## 2단계: dry run (읽기만, 쓰기 0회, **직접 연 터미널**에서)
1단계가 모두 통과한 뒤에만.
```
bash scripts/g01_5b4_s42_run.sh --set 16
```
화면에서 확인할 것:
- `집합 16 … 이동 50회` 또는 `이동 51회`. **시작 J4가 91로 읽히면 50, 92로 읽히면 51**이다(여덟 가지 시작 회독 조합을 오프라인으로 모두 확인했고 J2·J3는 영향 없음; 근거리 M3 때 래퍼와 러너의 J4 첫 읽기가 91/92로 갈렸다). 탐침은 항상 40이동이고 **`[이동 …]` 안내에서 J2·J3의 목표가 위·아래로 번갈아 나온다**(J2 91→90→89→90→92…). **이동 수가 50·51이 아니면 n.**
- `게이트 통과`, 충돌 검증 `전체 최소 … 기준 20.0 → 통과`(**20.0** 확인, `P1_GATE_MM`이 바뀌면 기준이 달라진다), 최소 여유 **블록 약 27, 종이 약 56, 베이스 약 39 mm**.
- 충돌 검증은 상태 52개라 **약 60~68초**(실측) 걸린다. 멈춘 것처럼 보여도 기다린다. `--real`에서도 같은 시간이 든다.
- 안전 질문 7개(6번은 J2·J3·J4와 오므린 그리퍼 서보 J6 발열 확인) → 모두 확인되면 **y**. 이후 `[이동 n/50]`(또는 51)이 표시되지만 서보는 움직이지 않는다.
- **성공:** `기록 확인: mode= dry_run ended= completed …`. dry run은 원시 값 읽기(`raw_after`)를 하지 않는다(원시 읽기는 1단계 점검 표본과 가짜 시험으로 확인).

## 3단계(별도 승인 뒤): `--real`
승인 요청 문서 §6의 R3에 사용자 승인이 기록된 뒤에만. 명령은 승인 후 별도로 안내한다(`*.sh` 안내 직전 advisor 검증). 실행 직전 순서: 점검 묶음 → dry run → `--real`(모두 같은 날, 블록·카메라·받침·팔을 만지거나 30분 넘게 지나면 점검부터 다시).

## 끝나면 알려 줄 것
1·2단계의 통과 여부와 마지막 몇 줄(실패 시 메시지 전문). 저는 dry run 기록 JSON에서 쓰기 0회와 이동 수, 충돌 검증 기준(`gate_mm 20.0`)을 직접 확인한다.

## 검증 근거
읽은 것: `scripts/p1_step_precheck.sh`·`p1_preflight.sh`·`g01_5b4_s42_run.sh`, 승인 요청 문서. 오프라인 실제 실행: `bash -n`(OK), 전체 테스트 148개 OK, 세트 16 계획·충돌 검증(최소 27.3/56.4/38.6, 기준 20.0), 가짜 시험 3종(방향별 정지 오차 모사·정확한 팔·중단)과 분석 복원, 오프라인 점검(`--readback`)에서 `scripts_sha256 n=17`·`src_sha256 n=20` 통과. **미검증:** 새 묶음 래퍼와 점검의 실기기 실행, 래퍼 `--check`·dry run의 세트 16 분기(Jetson 접속), 래퍼가 세트 16에서 DaBai 드라이버를 건너뛰는 경로(`--real`에서 처음 실행).
