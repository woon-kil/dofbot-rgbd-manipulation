# 점검 기록 파일 와일드카드 삭제 이슈보고서 (2026-11-15, 세션 A)

## 현상
출발 전 공통 점검의 오프라인 시험 뒤 내가 만든 시험 기록을 지우려고 `rm -f evidence/G06/p1_preflight_26111[0-9]*.json`을 실행했다. 이 패턴은 `261115-…`로 시작하는 **모든** 점검 기록에 일치해, 사용자가 실기기에서 실행한 점검 기록 두 건 `p1_preflight_261115-105756.json`(10:57, 실패)과 `p1_preflight_261115-110915.json`(11:09, 통과)과 오프라인 재점검 기록 `…-110509.json`까지 삭제했다. 해당 파일은 git에 추적되지 않아 복구할 수 없다(휴지통에도 없음).
```
$ ls evidence/G06 | grep -c "p1_preflight"
0
$ git ls-files --error-unmatch evidence/G06/p1_preflight_261115-110915.json
error: pathspec 'evidence/G06/p1_preflight_261115-110915.json' did not match any file(s) known to git
```

## 원인
- 시험이 만든 파일을 **정확한 이름으로 지우지 않고 날짜 접두 와일드카드로** 지웠다. 같은 접두를 가진 사용자 실행 기록이 이미 같은 폴더에 있었다.
- 기록 파일 이름이 날짜+시각뿐이라 시험 산출물과 실기기 기록이 구별되지 않았다.
- 한 번 지우는 명령이라 사전 확인(`ls`로 일치 대상 확인)을 생략했다.

## 수정
- 원본 기록은 복구 불가이므로 **사용자가 붙여 준 터미널 출력을 그대로 옮긴 전사본**을 증거로 보존했다: `evidence/G06/p1_m3_precheck_terminal_transcripts_261115.md`(원본이 아니라는 사실과 삭제 경위를 파일 머리에 명시). 승인 요청 문서의 인용도 전사본으로 바꿨다.
- 남아 있는 원본 증거: Jetson 설치본 함수 소스 `data/refs/jetson-Arm_serial_servo_read-261115-105756.py`·`-110915.py`, dry run 기록 `evidence/G01/raw/g01_5b4_s4214_result-dry_run-261115-105808.json`.
- 손실된 정보: 점검 JSON의 세부 필드(원시 표본 20회 값, 영역별 값). 점검 판정과 요약 값은 터미널 출력(전사본)에 있다. 점검 결과의 사실(통과/실패, 값)은 바뀌지 않는다.

## 교훈
1. **사용자 실기기 기록이 들어 있는 폴더에서는 와일드카드로 지우지 않는다.** 시험이 만든 파일은 만들 때 이름을 변수로 저장했다가 **그 이름으로만** 지운다(또는 시험 출력 경로를 증거 폴더가 아닌 임시 폴더로 보낸다).
2. 삭제 명령 전에 **같은 패턴으로 `ls`를 먼저 실행해 일치 대상을 눈으로 확인**한다.
3. 시험용 기록과 실기기 기록은 이름에서 구별한다(예: 오프라인 시험은 `--out`으로 임시 경로 지정).
4. 이 사고를 알게 된 즉시 사용자에게 알린다(이 문서는 보고와 함께 작성).

## 검증 근거
읽은 것·실행한 것: 위 두 명령의 실제 출력, `ls data/refs | grep jetson-Arm`(원본 두 개 존재 확인), `ls evidence/G01/raw | grep s4214`(dry run 기록 존재). 전사본은 사용자가 대화에 붙여 준 출력 그대로다.
