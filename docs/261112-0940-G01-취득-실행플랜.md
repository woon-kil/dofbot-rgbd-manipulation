# G01 두 카메라 취득·Gemini 시야 실행 플랜 (읽기 전용)

근거: `docs/gates/roadmap.md` G01, `docs/agent-work-order.md`, G00 결과(`docs/261112-0908-G00-인벤토리-결과보고서.md`), 진단 P1-8. 사용자 지시: "G01 시작해". 승인 경로: 이 프로젝트 설정(codex 대신 advisor 검토).

## 목표 / As-Is / To-Be
- 목표: Gemini 335L과 DaBai 각각에서 RGB·깊이·내부 파라미터·프레임 ID·타임스탬프·정합 여부·유효 깊이율을 취득하고, **취득 설정(깊이 스트림 해상도, Gemini 시차 탐색 폭, 정합 모드)을 함께 기록**한다. Gemini의 기존 고정 위치에서 작업영역이 보이는지 판정한다.
- As-Is: DaBai 내부 파라미터와 기본 설정(`depth_registration=false`)만 안다(G00). Gemini는 장치 존재만 확인, 펌웨어·설정·영상 없음.
- To-Be: `evidence/G01/`에 manifest, 설정 기록, 통계 JSON, 판정 문서가 있고 영상 원본은 gitignore 폴더에 있다. 판정은 `BLOCKED_GLOBAL_FOV`/미정합 여부를 근거와 함께 적는다. PASS 임계값이 동결 전이므로 **수치는 기록하고 PASS/FAIL 판정은 "임시 판정(PROVISIONAL)"으로 표기**한다.

## 실행 규칙 (강제)
- **로봇 이동·쓰기·조회 명령 없음.** 팔은 현재 자세를 유지한다. SDK `Arm_Lib` import 금지(G00과 동일). DaBai 드라이버를 띄우기 전 Jetson 사전 점검(팔 제어·카메라 구독 프로세스 없음) 재확인, 있으면 멈추고 보고.
- **두 카메라는 순차 촬영.** 한쪽 스트림을 끄고 확인한 뒤 다른 쪽을 켠다(IR 간섭 방지). 동시 촬영 시험은 하지 않는다.
- **p620 공유 서버:** 이 프로젝트 전용 컨테이너 이름(`dofbot-g01-camera`)만 만들고 지운다. 다른 컨테이너를 멈추거나 변경하지 않는다. 카메라 USB를 다른 컨테이너·프로세스가 쥐고 있으면(`fuser`, `HostConfig.Devices`) 촬영하지 않고 보고한다. 컨테이너는 촬영 직후 항상 정리한다.
- Gemini의 고정 위치를 건드리지 않는다. 카메라는 사용자가 놓은 그대로.
- 자동 노출이 수렴하기 전 프레임은 버린다(이전 프로젝트 이슈: 첫 프레임이 어두움). 워밍업 시간을 두고 노출 값을 기록한다.
- **영상은 개인 공간 사진**이라 `evidence/**/*.png` 등은 gitignore 대상이다(기존 규칙). 커밋은 manifest·통계 JSON·판정 문서만. 원문 로그는 `evidence/G01/raw/`(gitignore). 커밋 전 IP·시리얼·사용자명 grep.
- 임계값 미동결: 숫자를 기록하되 PASS를 단정하지 않는다. 충돌하는 출처는 실기기 우선, 모호하면 UNVERIFIED.
- 실패·타임아웃이 2~3회 반복되면 멈추고 보고한다.

## v2 — advisor 검토 반영 (실행 전)
1. **p620 실행 경로:** Mac에서 `ssh p620`로 명령을 보낸다. p620에는 이 프로젝트 전용 작업 폴더 `~/dofbot-g01-work/` 하나만 만들고(경로 기록), 종료 시 정리한다. 컨테이너 이름은 `dofbot-g01-camera`만 조작하며 `docker rm -f`도 이 이름에만 쓴다. **`learned-grasp-camera`(이전 프로젝트 컨테이너)는 절대 건드리지 않는다.**
2. **드라이버 볼륨:** 먼저 `docker volume ls`로 `bytesize-robotics-camera-install` 볼륨 존재를 확인하고 반드시 `:ro`로 마운트한다(다른 프로젝트 자산, manifest에 출처 기록). 볼륨이 없으면 멈추고 보고한다. 결과는 컨테이너 `/tmp`에 저장 → `docker cp`로 작업 폴더 → scp로 Mac → p620 작업 폴더 삭제. root 소유 파일은 `docker exec -u 0 chown`으로 정리한다.
3. **영상과 파생물은 전부 `evidence/G01/raw/` 아래**(통째로 gitignore). `.gitignore`에 `evidence/**/*.svg`도 추가했다. 커밋 전 `git status --porcelain`으로 추가 파일이 JSON·MD뿐인지, 통계 JSON에 시리얼이 섞이지 않았는지 grep한다.
4. **시야 판정 기준(촬영 전 고정, 수치 임계값 없이 기록):** ① 로봇 베이스 전체가 화면에 들어오는가 ② 작업 보드(영역) 네 모서리가 화면에 들어오는가 ③ 현재 팔 자세가 영역을 가리는가 ④ 영역 ROI 안의 깊이 유효율. 마스크는 초안이고 실제 사진 위 SVG로 사용자 확인을 받는다. 판정은 PROVISIONAL.
5. **통계 JSON 필드:** `RgbdFrame` 계약에 맞춰 `camera_id, frame_id, depth_unit_m, aligned_to_rgb, capture_time_ns, clock_domain`을 기록한다(DaBai 깊이 단위는 G00 미확인 항목이므로 `enable_depth_scale` 설정과 함께 실측으로 확인).
6. **시계:** Jetson과 p620 각각 `timedatectl show`로 NTP 동기 상태를 기록한다. 두 장치의 타임스탬프를 서로 빼지 않는다.
7. **스크립트 해시:** 사용한 스크립트(`scripts/`는 추적 제외)의 sha256을 manifest에 남긴다.
8. **설정 변경 금지:** Gemini 정합 설정은 이전 프로젝트 파라미터(`depth_registration:=true align_mode:=SW align_target_stream:=COLOR`)를 쓴다. 시차 탐색 폭이 launch 파라미터로 노출되지 않으면 장치 속성을 쓰거나 바꾸지 않고 UNVERIFIED로 기록한다.
9. **중단 조건:** 팔 제어 프로세스 발견, 카메라 USB를 다른 컨테이너·프로세스가 점유, 드라이버 볼륨 없음 → 멈추고 보고.
10. **캘리퍼 측정 안내:** G01에서 그리퍼가 보이는 사진이 있으면 그 위에 측정면 SVG를 그려 사용자에게 안내한다(사용자 규칙).
