# 방향 점검 보고서 (6a53e85 이후 구간: dry run 결과, 낙하 뒤 복귀 간격, 죽은 터미널 결함)

점검 주체: 세션 a8. **자기 산출물을 평가하는 한계가 있다.** 이 구간의 실기기 기록은 로봇 **0건**. 사용자가 사진 경로 dry run(p620 카메라, 로봇 명령 없음)과 러너 dry run(쓰기 0) 및 수동 러너 dry run을 실행했다.

## 실행한 확인 (실제 출력)
```
$ python3 tools/verify_records.py → 항목 81, 복사본 정상 81, 원본 로컬 없음 0, 문제 0
$ .venv/bin/python -I -m unittest discover -s tests → Ran 318 tests OK (skipped=1)          (venv)
$ python3 -m pytest -q tests/test_lift_dryrun.py tests/test_lift_bridge.py tests/test_lift_r8.py → 시스템 python(의존성 없는 시험은 건너뜀), 위와 합산하지 않음
$ python3 tools/direction_check.py --status → 스냅샷과 다른 실행 스크립트 수: 0
```

## 병목 재판정
**병목 행은 그대로**(들어올림 판정 기록 0, 해소 조건 = 판정이 난 기록 1건). 달성하지 않았다. 새 병목이 더 앞에 있다는 신호는 없다. 이 구간에 가장 큰 미측정 위험(사진 대기 3.0 s 창)이 실측으로 닫혔고(최대 D 1.81 s, 여유 1.19 s), 낙하 뒤 복귀 경로의 간격 한계와 **죽은 터미널에서 비상 열기가 건너뛰어지는 안전 경로 결함**을 `--real` 전에 찾아 고쳤다.

## 우려와 근거
1. **래퍼 경유 dry run의 `result.json` 미생성 원인이 미증명이다.** 죽은 pty 가설이 유력하나 그 실행의 출력이 사라져 확인할 수 없다 → 리허설에서 러너 출력 로그(`RLOG`)와 진단으로 확인.
2. **러너 코드 변경이 늘었다**(`say` 한 함수, 낙하 뒤 질문). 세트 31 회귀는 일치하나 `--real` 직전 최종 상위 검토에서 다시 본다.
3. 사진 경로 dry run은 정지 K1·Q0 입력이다. 실제 누름 중 D는 첫 사진 A에서 확인.
4. 점검 알림이 작은 단위 커밋으로 반복해 발화한다.

## 권고 (우선순위)
1. 사용자 실행: 래퍼 리허설(`bash scripts/g01_lift_run.sh`, `--real` 없음).
2. 사용자 판단: E1 선(들어올림 높이).
3. `--real` 전 필수 잔여: 리허설 결과 확인, 스냅샷, 코드 최종 상위 검토, E-5 복원 SVG(승인 요청 확정 직전), 승인 요청 확정, 사용자 `--real` 승인.
4. STATUS 행 52의 `17:xx` 라벨 정정.
