# M0 래퍼 `git_head` 기록 누락 이슈보고서 (2026-11-19, 세션 f8)

## 현상
- 사용자가 `bash scripts/g01_m0_run.sh --sanity`를 실행했고, 저장된 sanity 기록(`evidence/G01/raw/g01_m0_readonly_sanity_261119-112706.json`)에 `git_head` 키가 없었다. 사용자가 "제시 전에 코드 검증했나?"라고 물었다.
- 사전 등록한 "코드를 측정에 결속(기록에 `git_head` 저장)"이 sanity 경로에서 작동하지 않았다. 도구·읽기 측정 자체와 시간 값은 정상이다.

## 원인
- 커밋 `760f7ef`의 래퍼 마지막 python 줄이 `sys.argv[2]`를 쓰는데 인자 `"${GITHEAD}"`를 넘기지 않았다(IndexError, 래퍼가 그 줄에서 종료 코드 비0).
- 앞 수정에서 `str.replace`로 인자를 붙이려 했으나 치환 대상 문자열이 실제 줄과 맞지 않아 **아무 일도 일어나지 않았고**, 일치 개수를 단언하지 않았으며 수정한 줄을 실행해 보지 않고 커밋했다. 제시 전 검증은 로컬 가짜 팔·`--check`·인자 오류까지였고 Jetson 실경로와 마지막 줄은 실행하지 않았다.

## 수정
- 해당 줄 끝에 `"${GITHEAD}" || echo "경고: ..."` 추가(커밋 `e2a8556`). 원본 sanity 기록은 증거라 고치지 않았고 플랜에 "코드 커밋 `760f7ef`로 간주(도구 변경 없음)"로 적었다.
- 추가로 아직 실행된 적 없던 "본 측정 기록이 있으면 거부" 줄을 `set -euo pipefail` 맥락에서 빈 폴더(통과)·더미 파일 폴더(exit 7)로 따로 실행해 확인했다.

```
고친 줄 실행(복사본): 코드 커밋: abcdef1234 / 기록 확인: mode= real_readonly sanity= True n= 3 소요 s= 19.7 중지= None / git_head 기록됨: abcdef1234567
재측정 거부 줄(set -e 맥락): empty → 통과(다음 줄 실행됨) exit 0 / dummy → 거부 exit 7
Jetson: Python 3.10.12, py_compile 문법 OK, Arm_Device에 addr·bus·Arm_serial_servo_read 있음
```

## 교훈
1. `str.replace`는 일치하지 않으면 조용히 아무것도 하지 않는다 → 개수를 단언하고, 수정한 줄을 그대로 실행해 본 뒤 커밋한다.
2. 사용자에게 실행을 안내하기 전에 실경로(원격 실행·결과 수집·후처리)를 가능한 범위에서 모두 실행해 본다. 아직 실행되지 않은 줄도 따로 실행한다(재측정 거부 줄).
3. 측정 전 결속 장치는 기록에 실제로 들어갔는지 결과 파일로 확인한다.
