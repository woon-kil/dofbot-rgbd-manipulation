## 우려와 근거
1. **M2c 0.0은 약한 증거다.** 정지 장면에서 같은 프레임 내용이 같은 정수 꼭짓점을 낳아 한 기동 안 10장이 동일하다. 같은 도구 2회차의 기동 안 최대는 0.5257였다. 성립은 "사전 등록 시험을 통과했다"이지 "들어올림 신호가 잡음 위로 확실히 나온다"가 아니다. 문턱 여유(T=0.7, 부족 1.5°에서 0.01)와 블록 밀림·쥔 자세 영향(E-2b §12 열린 위험 2건)은 P-A와 무관하게 남았다.
2. **사진 A·B가 서로 다른 P-A 기동에서 오면** 기동 간 차이(이번 0.261 px)가 신호에 더해진다. 러너 플랜에 `started_epoch` 일치 규칙을 넣어야 한다(보고서 §6 안 A).
3. 결과 전달 경로 지연은 미측정이다(플랜 `:68`: 들어올림 러너 dry run에서 측정). 누름 창 25 s 상한 안에 들어갈지는 그때까지 확정이 아니다.
4. P-B·배치 사진 도구의 입력 버퍼 `tcflush` 수정은 여전히 미구현이다(재실행 전 필수).
5. 점검 알림이 작은 문서 정정 단위의 커밋으로 반복해 발화한다(이번에도 커밋 12개).
