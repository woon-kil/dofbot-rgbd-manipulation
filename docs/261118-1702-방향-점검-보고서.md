## 병목 재판정
**병목 행은 그대로**(접촉 정체 2/2·형태 미확정·들어올림 실기기 기록 0, 해소 조건 = 블록을 쥔 상태의 들어올림 1회). 이 구간은 해소 조건을 달성하지 않았다. 새 병목이 더 앞에 있다는 신호는 없다. 다만 **`--real` 시작 단계를 막던 구멍(G2 `d_x`, 정렬 확인, 마커 기준)이 모두 닫혀** 코드 쪽 준비는 `--real` 직전에 가까워졌고, 남은 차단은 절차(사용자 승인, 스냅샷, dry run, 낙하 뒤 물러남 등)다.

## 우려와 근거
1. **증거 범위 과대 서술이 반복된다.** '31041 = press 상태'는 값(Δx)만 보고 기록(`hold_3104_released`, epoch)과 대조하지 않은 데서 나왔다. 앞으로 "관측했다"고 쓰기 전에 사진·값의 시각을 기록과 대조한다.
2. **순서 규칙 위반 1회:** 설계→검토→코드 순서를 P10 런타임 확인에서 어겼다(정정 기록됨).
3. **첫 시도 성공 확률:** 정렬 여유 0.63 mm와 J1 변동(1°에 약 3 mm)이 겹치면 첫 실행이 정렬 NG로 멈출 수 있다(안전한 방향, 시도 아님 분류). 쥔 상태 G4가 0.75 px 문턱에 얇을 수 있다.
4. 사진 대기 3.0 s 안의 Mac→Jetson 쓰기 시간은 미측정(dry run N=20).
5. 점검 알림이 정정·라벨 커밋에도 발화한다.

## 권고 (우선순위)
1. 사용자: 사진 A no-go의 시도 분류, P10 처짐 한계 A/B 결정(B는 설계 상위 검토 뒤 구현).
2. `--real` 전 필수: dry run(사용자 실행, N=20) 시간 측정, 스냅샷, 래퍼 실행 요청 직전 advisor, 낙하 뒤 물러남·E-3·E-5 복원 절차(SVG)·복귀 경로 간격, R8 Mac 사후 계산, 승인 요청 확정, 사용자 `--real` 승인.
3. STATUS 행 52의 `17:xx` 임시 라벨을 실제 값으로 정정.
