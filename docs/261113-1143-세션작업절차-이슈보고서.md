# 세션 작업 절차 이슈보고서 (실행 중 도구 수정, heredoc 백틱)

## 현상
1. S4-6 `--real`을 사용자가 실행하는 동안 `scripts/`(계획기·실행 도구·촬영 도구)를 고쳤다. 결과 출력(3초 대기, J1 3000 ms)으로 보아 구버전으로 일관되게 실행됐지만, 계획기와 실행 도구가 서로 다른 버전으로 섞여 실행될 수 있었다.
2. 따옴표 없는 heredoc(`<<E`) 안의 백틱 문구가 셸에서 명령으로 실행되어 문서가 일부 비거나 생성이 실패했다(`permission denied`, `command not found: --set`). 두 번 발생.

## 원인
1. 안내 후 결과를 받기 전 `scripts/` 고정 규칙이 없었다. 속도 상향 요청을 즉시 반영하려다 실행 시점과 겹쳤다.
2. 문서 본문에 `코드`용 백틱이 많아 인용 없는 heredoc을 쓰면 명령 치환이 일어난다.

## 수정
- 실행 명령을 안내한 뒤 결과를 받기 전까지 `scripts/`를 고치지 않는다. 변경이 필요하면 다음 취득용 문서에 해시와 함께 기록하고 실행 전 advisor 검증을 거친다.
- 본문에 백틱이 있는 문서는 `<<'EOF'`(인용)로 쓰거나 템플릿 파일을 쓰고 치환한다.
- S4-6 이후 실행 도구 해시를 승인 문서에 기록한다(S4-6 `b2e51bf9…`, S4-7 문서에 갱신 해시).

## 교훈
- 실행 중 도구는 불변이다. 속도 변경 같은 요청도 "다음 취득부터"로 분리한다.
- 생성 문서는 쓰고 나서 `grep`으로 빈 칸·누락을 확인한다.
