## 2. 해석
- **S1 감소 방향 세 관절(J4·J3·J2) 모두 같은 패턴이다.** SDK 감소(raw 증가) 이동은 목표 81보다 1° 부족한 82에서 멈추고(관절마다 2회), 증가 방향 복귀는 91에 정확히 도달한다(R27, 10° 폭). 세 관절의 8000 ms 이동 정착은 7527(J4)·7220(J3)·7219 ms(J2), 시계열 1초 간격 값은 J3와 J2가 같은 값(91, 90, 89, 87, 86, 85, 84, 82, …)이다.
- **기운 방향:** 세 관절 모두 SDK 감소 = 앞(사용자·보드 쪽). 가장 하중 모멘트가 큰 J2도 처짐·접촉 없이 10° 이동을 마쳤다.
- **1500 ms 이동은 1.047~1.050배**로 J1·J5·J4·J3와 같다. 이번에는 `None` 영향이 없었다.
- **S1 목표(승인 문서의 감소 방향 3관절)는 충족.** plus 방향 10°는 보정 자세에 필요 없을 수 있어 선택 사항으로 남긴다.

## 3. 이슈 — 이동 직전 비프음이 나지 않음
- **현상:** 이동 안내 줄(`[이동 N/4] ... 3초 뒤 이동합니다`)은 출력됐으나 소리가 나지 않았다(사용자 보고).
- **원인(추정, 미확인):** 비프음을 터미널 벨 문자(`\a`)로 구현했다. 가짜 시험에서는 출력에 벨 바이트가 있는지만 셌고 **실제 소리가 나는지는 확인하지 않았다**(advisor가 지적했던 사항). 맥 터미널의 경고음 설정 때문으로 보이나 설정은 확인하지 못했다.
- **수정:** `scripts/g01_5b4_run.sh`가 시험 출력에서 `[이동 N/4]` 줄을 보면 **맥에서 `afplay`로 Glass 소리를 낸다**(터미널 설정과 무관). 출력은 `tee`로 그대로 통과한다. 검증: 감시 루프 단독 시험에서 줄 2개에 소리 2회, 실제 ssh 터미널을 거친 통과 시험에서 안내 줄 감지 1회·질문 표시·입력 통과 확인. **실제 소리가 사용자에게 들리는지는 다음 실행에서 확인한다**(`afplay` 단독 재생은 이번 세션에서 오류 없이 실행됨).
- **교훈:** 소리·화면 같은 사용자 감각에 의존하는 안내는 "코드가 출력했다"가 아니라 실제로 지각되는지를 첫 실행 전에 확인해야 한다. dry_run에서 질문마다 소리가 났는지 물었어야 했다.
