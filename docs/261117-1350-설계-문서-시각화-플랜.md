# 설계 관련 문서 시각화 플랜 (2026-11-17, 승인 대기 — 구현 전)

## 1. 목표
설계 관련 문서를 **처음 보는 사람이 길을 잃지 않고 읽을 수 있게** 그림·지도로 보여 준다. 병목(접촉·파지·들어올림 실기기 기록 0개, `PROJECT-STATUS.md` '현재 병목' 행)을 직접 줄이는 작업은 아니므로 **작게, 자동 생성 가능한 것만** 한다. 새 안전 한도·시험·하드웨어 명령은 없다.

## 3. 목표 상태(To-Be)
1. **설계 문서 지도**(표+그림): 범위 10개 문서 각각의 "무엇을 정하나 / 어떤 문서·기록에 기대나 / 결정 칸 확정 수 / 마지막 수정일".
2. **변환 그래프 도식**(`system-design.md` 글을 그림으로): 두 카메라 → 베이스 좌표 변환 연결.
3. **ADR 한 장 요약**: 7개의 제목과 서로 인용하는 관계. 측정 결과 '결정' 줄이 있는 ADR은 7개 중 3개(001~003)뿐이고 서로의 인용은 3쌍(005→003, 007→003, 007→005)뿐이다. 결정 줄이 없는 4개는 표에 "결정 줄 미추출"로 두고 지어내지 않는다.
4. (선택, 보류) 첫 접촉 시험 측면 도식 — §6.

## 7. 리스크·Pre-mortem
| 실패 이유 | 예방 |
|---|---|
| 1. 문서의 "인용"이 형식이 제각각이라 관계를 못 뽑거나 틀리게 뽑는다 | 백틱 안의 `docs/...md` 경로만 인용으로 센다. 판독 불가는 그리지 않고 "미추출"로 표에 남긴다 |
| 2. 만든 지도가 곧 낡는다 | 생성 명령 한 줄과 기준 시각을 지도에 적는다. 훅 자동화는 하지 않는다(설정 변경은 사용자 승인) |
| 3. 병목이 아닌 문서 작업에 시간을 쓴다 | 단계 1~5 모두 합쳐 소규모로 제한하고, 세션 A의 Run 3 준비를 방해하지 않는다. 상위 등급 검토가 필요한 안전·시험 문서는 건드리지 않는다 |

## 8. 완료 기준
- `design-doc-map.md`와 SVG가 범위 10개 문서를 모두 담고, 깨진 인용 경로가 0이거나 표에 명시된다(사전 측정: 10개 문서 모두 깨진 경로 0).
- 그린 선 수와 추출한 인용 수가 스크립트로 일치한다.
- 변환 그래프 SVG가 `system-design.md`의 식과 역산 대조 표로 일치한다.
- Chrome 전체 렌더링에서 글자 잘림·겹침이 없다.
- 단위 테스트 통과, 입문 문서에 링크, 하드웨어 명령·새 안전 한도 없음.
