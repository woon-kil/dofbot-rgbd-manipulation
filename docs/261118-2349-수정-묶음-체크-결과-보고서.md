## 4. T9·T10: 셋째 이동(J4)의 이탈 검사 (사용자 승인 2026-11-19로 `cmd` 갱신 적용)
- **수정 전 기록(현재 동작):** `run_move`는 명령하지 않은 관절을 `cmd`와 `HOLD_TOL = 3`으로 비교한다(`g01_p2k_test.py:14, 128행`). 둘째 이동 뒤 `cmd[2]`에는 목표 77이 남고 실제 J2는 서보 부족분만큼 낮아, 가짜 팔에서 셋째 이동 중 추가 처짐 3°부터 중단됐다(`J2 회독 73가 현재 명령값 77에서 3° 넘게`). 실기기 부족분은 재실행 #1에서 2°(둘째 이동 뒤 J2 75, 가짜 팔은 76)라 여유는 약 1°.
- **수정:** `g01_lift_hook.py` `do_move`가 이동 성공 뒤 `cmd[joint]`를 `st["final"][joint]`(run_move가 이미 모은 실제 정수 회독)로 갱신한다. 새로 읽지 않고 None이면 목표값을 유지하며 `HOLD_TOL`과 `run_move`는 불변이다. 기준점이 바뀌어 같은 3°가 회독이 높은 쪽(처짐 반대)에서는 더 엄격하고 낮은 쪽에서는 느슨하다.

## 5. 세 번째 결함 여부
- `P2K["start_all"]`과 `do_return`에 넘기는 `start_all`은 같은 객체이다(`g01_p2k_test.py:425` `start_all = dict(state); P2K["start_all"] = start_all`, 541행에서 같은 dict의 [6]을 갱신). 비상 열기 뒤 복귀 첫 이동의 J6 HOLD 검사는 T1·하네스 hangup에서 통과했다. **세 번째 결함은 발견되지 않았다.**
- 단 T9에서 드러난 셋째 이동 이탈 검사 여유는 별도 위험(등급 A 대기)이다.

## 6. 남은 위험 (승인 문서에 적을 것)
- 버스 None이 난 직후 `do_return`이 어댑터를 다시 만들며 읽으므로 다시 None이면 팔이 들린 채 멈춘다(복구: 제어보드 K1 한 번, 사용자 경험, DOFBOT Pro 문서 미확인).
- 비상 열기 대체 어댑터(`g01_p2k_test.py:539-540`)의 `read_start`가 None이면 J6가 눌린 채 남는다(동작 변경 범위 밖).
- None의 원인(서보 통신)은 미확정, 오프라인 재현 불가. 이번 수정은 결과(복귀)를 바로잡는 것이고 `lift.adapter_logs`가 다음 None을 기록한다.
