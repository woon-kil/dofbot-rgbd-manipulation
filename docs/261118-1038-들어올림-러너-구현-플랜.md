## 1. 설계 방향 (권장: p2k 러너 확장)
새 스크립트를 쓰지 않고 **기존 p2k 러너에 새 세트(예: 33, "Run 5 들어올림")를 추가**한다. 정렬(J1 86, y/N)·하강·높이 관문·접촉 닫기(`poll_stall`)·열기·복귀·`tcflush`(`inp`)·이동 직전 소리가 이미 승인·실행 검증돼 새 안전 코드가 늘지 않는다. 대안(별도 스크립트)은 접촉 규칙을 복사해 승인 범위가 갈라지므로 택하지 않는다.

**코드에서 확인한 제약(설계에 반영):**
- **F1 Gemini 점유 충돌:** 래퍼의 기준 사진 마커 관문·`gemini_photo_bg`·복귀 뒤 사진은 36 s 도구(`p1_m3_gemini_photo.sh`, 자체 드라이버를 띄움)를 쓰고, P-A 드라이버가 Gemini USB를 잡는 동안에는 점유 검사(`pa_driver.sh:46` 방식)로 실패할 것으로 본다(36 s 도구 본문은 미읽음 — 구현 때 확인). **규칙: 이 세트의 실행 중 Gemini 사진은 모두 P-A 스냅(`pa_snap_mac.sh`)이며 36 s 도구는 부르지 않는다. 래퍼 새 분기를 만들고 기준 사진·사진 A·B·복귀 뒤 사진을 P-A로 바꾼다.** 복귀 뒤 사진을 P-A로 대신하는 것이 Run 3·4의 S4 주 판정과 동등한지는 미검증이라 승인 항목에 올린다(P4).
- **F2 닫기 순서:** 145를 먼저 쓰고 150에서 정체했다(Run 3·4). 누름은 145 단계부터 시작한다.
- **F3 어댑터는 사전 승인 목록 기반**(`set_targets`·`max_writes`)이다. 두 번째 J2 명령이 원시 읽기로 정해지므로 `run2_hook`의 `mk(...)`처럼 **이동 직전에 어댑터를 새로 만든다**(목록 안에 허용 범위 포함). 어댑터 본문은 미읽음.
- **F5 상태 인계(읽은 코드 근거):** `run_move`는 main이 만든 `ads[j]`(계획 목록 기반 어댑터)·`cmd`·`start_all`을 쓰고 `cmd[j]=tgt`를 갱신하며 비명령 관절을 `cmd`와 ±3°, J5·J6를 `start_all`과 ±3°로 감시한다. `GripperTestAdapter`는 `set_targets`를 **한 번만** 받고 `move`는 다음 승인 목표만 허용하며 `_check_speed`는 직전 명령 위치에서 60 ms/° 이상을 검사한다. 따라서 **들어올림 훅은 이동마다(두 번째 J2는 값을 읽은 뒤) 새 어댑터를 `mk`처럼 만들어 로컬 `ads`에 넣고, main의 `cmd`·`start_all`을 그대로 `run_move`에 넘겨 갱신되게 한다. 정체 뒤 `start_all[6]`을 정체 회독(예 146)으로 갱신**해 J6 감시가 눌린 값을 기준으로 하게 한다. 훅 이동은 `PROG["sent"]`를 바꾸지 않는다(phase를 A·B·T로 두지 않음). 이 규칙이 빠지면 `run_move`가 들어올린 J2·J4 값을 '명령하지 않은 관절 이탈'로 오인하거나 어댑터가 쓰기를 거부한다.
- **F5b 첫 이동 규칙:** 어댑터 `first_move_min_ms`는 첫 쓰기가 그 값보다 짧으면 거부한다. ADR-005 `:22·:27~30`: 이전 프로젝트 상한 '첫 이동 8000 ms'를 동결하고 'G01.5b-3부터 어댑터 `first_move_min_ms`로 코드 강제'(팔 관절 서보를 처음 움직이는 이동이 대상, `make_adapters`는 8000). 들어올림은 같은 세션에서 J2·J4를 이미 움직인 뒤(접기·하강)이며 `do_return`과 접촉 닫기 어댑터는 `None`을 쓴 선례가 있다. **새 어댑터를 `None`으로 두는 것은 ADR 규칙의 해석이므로 조용히 정하지 않고 P7로 올린다.** 8000 ms를 쓰면 예산이 성립하지 않는다.
- **F6 복귀 경로 제약(읽은 코드 근거):** `do_return`은 `plan["return_routes"][k]`의 계획 상태와 현재 J1~J4 회독이 3° 넘게 다르면 **쓰기 없이 멈춘다**. 들어올린 자세는 계획 상태가 아니므로, 정상 종료든 들어올린 뒤 중단이든 **들어올린 상태의 복귀 경로를 생성기가 미리 계산**해 `return_routes`에 넣어야 한다(`return_route`·FK 게이트 재사용, 부족분 변동(J2 ±수°)을 3° 안에 두는지 확인). **두 번째 J2 값이 3~6°로 정해지므로 후보 값(3·4·5·6°)마다 복귀 상태를 미리 계산하고 회독에 가장 가까운 것을 고르며, 3° 넘게 다르면 지금처럼 쓰기 없이 멈춘다.** 없으면 팔이 들어올린 자세에 남고 J6만 열린다(안전하지만 시험 뒤 수동 개입이 필요).
- **F4 중단 처리:** `main`의 `finally`는 접촉 중이면 J6를 연다. 들어올린 상태에서의 중단은 **J6 열기(낙하 ≤ 약 20 mm) → 팔은 내리지 않는다 → 기존 복귀 질문** 순서가 필요하다(새 분기).

## 3. 단계 (각 단계 끝에 advisor, `--real` 없음)
1. **착수 전 읽기:** 위 미읽음 파일. 어긋남이 있으면 이 플랜을 개정하고 다시 검토.
2. **구현·단위 시험:** 새 세트 계획(생성기 확장·FK 게이트·`carried_block_path_261117.py` 경로 점검 연결), 새 훅(`lift_hook` 형태), R8·R9 함수, 누름 시계·같은 기동 규칙 단위 시험, 가짜 팔(`FakeArmS`)로 흐름 시험(중단 주입: 사진 대기 초과·기동 불일치·26.8 s 초과·J6 None 연속 3회·정체 명령 150 미만·들어올린 상태 중단 F4·**들어올림 뒤 낡은 계획 어댑터로 다음 이동을 보내지 않음(남은 계획 이동 건너뜀)**·**들어올린 뒤 정상 종료 복귀(F5·F6: 새 어댑터·`cmd`/`start_all` 인계, 계획 상태와 3° 이내/초과 두 경우)**·**낙하 뒤 정상 복귀에서 K1 도착 전까지 J6 닫기 없음**·**들어올린 중 중단에서 `ad6c`로 J6를 한 번만 열고 `finally`가 다시 열지 않음**·경과 점검 실패 R6). dry run은 쓰기가 0회라 F5·F6 결함을 잡지 못하므로 이 가짜 시험이 유일한 점검이다. 시험 결과는 **시스템 pytest와 venv unittest를 따로** 보고한다(합산 금지).
3. **스냅샷:** 코드 변경 없는 커밋에서 `evidence/scripts_snapshot/<날짜>-lift1/`와 `MANIFEST.sha256`(기존 스냅샷 보존).
4. **dry run(사용자 실행, 쓰기 0회, 사전 지정):** Jetson에서 실제 `Arm_Lib` 읽기만. 사진 요청·확인·전달 경로를 p620 카메라로 **N = 20회**(간격 ≥ 5 s, A형 5회·B형 5회·교대 10회) 돌려 **D 분포**(요청 에포크 Jetson 시계, Mac 단계 시각 `m_start·m_scp_done·m_detect_done`, 확인 수신 에포크)를 기록하고 같은 기동 규칙·R6 점검을 확인한다. 팔 명령 없음. **이동당 시간은 dry run에서 쓰기를 보내지 않으므로 잴 수 없다**(E-2b §13의 해당 문구는 이 플랜과 함께 정정): 실기기 전까지 Run 4의 이동 기록을 쓰고 실기기 후 확정한다.
5. **결과 보고:** 증거 추적 복사, advisor 상위 검토 뒤 사용자에게 보고. 이후 §6 항목은 별도 플랜·승인.

## 5. 열린 위험
- **E-2a 미확인:** 닫힌 상태에서 마커 id 7이 보이는지 후속 결과를 찾지 못했다(`grep E-2a docs`: 설계·승인 문서뿐이고 E-2b `:18` "P-A 후 가능"). 이 시험의 사진 A가 첫 E-2a 데이터다. 보이지 않으면 G1 때문에 **no-go가 나며 실기기 1회를 소모**한다. dry run으로는 확인할 수 없다.
- E-0G 신호가 파지 자세에서도 같은지 미확인, T=0.7의 여유 0.01(E-2b §12). 이 플랜은 이를 줄이지 못한다.
- D·이동당 시간 미측정, 복귀 시간은 추정.
- p620·Mac·Jetson 중 한 곳이 누름 중 끊기면 사진 대기 초과로 즉시 열기(예상된 실패). 끊김 감지는 새로 만들지 않는다.
- 미읽음 코드와의 불일치 가능성.
- 사진 B 결과를 누름 창 안에서 쓰지 않으므로 E-2b `:46`의 "E1 부족 → 즉시 열기"는 (나)에서 사후 판정이다(열기 순서는 동일). 승인 요청 확정 때 문구를 맞춘다.

## 6. 이 플랜이 끝나도 남는 것 (`--real` 전 필수)
R4의 **낙하 뒤 팔이 물러나는 이동**(손가락을 연 채 블록과 닿지 않는 경로, E-3 FK 점검 포함), **E-3 간격 점검 도구**(쥔 블록 경로: 손가락·링크·카메라), **E-5 블록 복원 SVG와 복원 절차**, **들어올린 상태의 복귀 경로 FK 간격 점검(F6: 생성기가 경로를 만들지만 블록·손가락 간격 승인은 별도)**, E-2b §13의 '+2D'와 사진 목록 정정, E-2b 승인 요청 확정과 사용자 `--real` 승인. 이들은 별도 플랜이다.
