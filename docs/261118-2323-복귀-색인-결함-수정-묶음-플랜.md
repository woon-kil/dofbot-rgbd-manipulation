## 1. 확인된 사실 (코드를 읽고 확인, 사후 분석은 "참고용, 결정 근거 아님")
1. **복귀 색인 결함(두 번째 사고 원인, 코드 확인):** `scripts/g01_lift_hook.py` `do_move`(155~170행)는 `PROG["sent"] = _idx(...)`(158행, 이 이동이 끝난 뒤 상태 색인)을 `_adapter(ctx, joint, target)`(159행)보다 먼저 쓴다. `_adapter`는 `try`(161행) 밖이다. `_adapter` 안 `ad.read_start()`(`gripper_adapter.py:69-76`)가 `GripperTestError("회독이 None이다")`를 내면 복귀 색인 복원(163~167행의 `PROG["sent"] = _stage_idx(ctx)`)에 닿지 않고 `PROG["sent"]`가 쓰기가 일어나지 않은 이동의 "끝난 뒤" 색인으로 남는다. `g01_p2k_test.py` main의 `except GripperTestError`(528행) → `finally`의 `do_return(..., PROG["sent"], ...)`가 그 색인(29: [86,75,12,27])을 쓰는데 실제는 [86,75,12,32](색인 28)라 `do_return`(560~566행)이 3° 불일치로 쓰기 없이 멈췄다(fail-closed로 안전했지만 팔이 들린 채 남음).
2. **None의 호출 지점(추정):** 셋째 이동 `lift3`(J4)의 `_adapter(ctx, 4, …)` → `read_start()`가 J4 회독 None을 만난 것이 가장 유력하다(이동 23 뒤 이동 24 안내 전에 예외, 쓰기 기록은 J2 두 개뿐). 새 어댑터는 결과 JSON에 로그가 없어 실행 기록만으로는 확정하지 못한다. `read_start`는 재시도 없이 한 번만 읽는다(`_raw`는 3회 재시도). None의 원인(서보 통신 일시 오류 등)은 **미확인**이다.
3. **분류기·문구:** `scripts/g01_lift_classify.py:35`는 `lifted_once = bool(lift.get("moves"))`, 사유 코드가 없으면 `UNKNOWN`이고 48행이 "첫 J2 이동 뒤 열림"을 붙인다(실제 J2 이동 2개 실행). 러너 안전 질문 2번(`g01_p2k_test.py`)과 래퍼 질문(`g01_lift_run.sh` QTXT)의 "재등록 사진(17:02) 이후 손대지 않았고"는 이번 블록 복원(0.75 px)으로 거짓이 되었다.
4. **도구:** `tools/make_lift_snapshot.py`는 인자를 검증 없이 이름으로 쓴다(`--help`가 폴더를 만듦).

## 3. 시험 (TDD: 수정 전 코드에서 실패 → 수정 후 통과)
- **T1:** 가짜 팔에서 `lift3`(J4) 어댑터 생성 시 J4 읽기를 한 번 None으로 만든다. 수정 전: `return_state_mismatch` 또는 `returned_to_start=False`. 수정 후: 비상 J6 열기 정확히 1회, 색인 28 경로로 복귀 완료, `returned_to_start=True`.
- **T2:** 같은 방식으로 `lift2`(J2 둘째 이동)와 `lift1`(첫 이동) 어댑터 생성에서 None → 각각 올바른 복귀 색인과 복귀 완료.
- **T3:** `_adapter` 실패 시 `PROG["sent"]`가 마지막으로 쓰기에 성공한 이동의 상태 색인과 같다(색인 값을 직접 단언).
- **T4:** 분류기: 사유 코드 `ADAPTER_BEFORE_WRITE`, `lifted_once` 의미, 문구에 실행한 이동 수. 기존 분류 시험 전부 유지.
- **T5:** M1의 읽기 순서 변경이 쓰기 직전 조용한 시간 규칙(읽기 직후 쓰기 폐기 0.3 s)을 깨지 않는다는 시험(가짜 팔의 `--fake-read-quiet` 사용).
- **T6:** 질문 문구 시험: 8항목 수·순서 불변, 고정 날짜 문구 부재(기존 `test_...` 갱신).
- **T7:** 스냅샷 도구: `--help`, `-x`, `a/b`, `..`는 거부하고 정상 이름은 통과, 거부 시 폴더가 생기지 않는다.
- 전체: `.venv/bin/python -I -m unittest discover -s tests`(현재 321 OK, skipped 2)가 새 시험 포함 전부 통과, 세트 31 회귀(`test_lift_hook` 회귀 3건) 일치.
- **재현 한계:** 가짜 시험은 None이 나왔을 때의 **결과 처리**를 검증한다. 실제 서보 통신에서 None이 왜 나는지는 오프라인에서 재현하지 못한다(원인 미확정). 승인 요청에 "원인 미확정 상태에서 결과만 바로잡는 수정"이라고 적는다.
- **보강 근거(참고용, 결정 근거 아님):** 재실행 러너 로그·결과 JSON에서 셋째 이동 직전 읽기 시각을 대조한다(`lift_runner_261118-222500.log`, `result.json`의 move 23 `series`).
