승인: 플랜 `docs/261117-2335-P-A-상시-드라이버-단일프레임-개발-플랜.md`(PA-1 설계·구현, PA-2 사전 등록 지표·문턱 동결). 문턱은 `scripts/pa_eval.py`의 코드 상수로 고정했고 결과를 보고 바꾸지 않는다.

## 구현 (스냅샷 `evidence/scripts_snapshot/261117-pa1/`, MANIFEST 6개 sha256)
| 파일 | 역할 |
|---|---|
| `scripts/pa_driver.sh` | p620에서 `ssh "ACTION=start\|stop\|status [WARMUP] [MAXSEC]" bash -s`. 컨테이너 `dofbot-g01-pa`, 원본 g01_gemini_check.sh와 같은 드라이버 인자·Gemini 점유 검사·종료 대기·정리. 컨테이너는 MAXSEC+60 s 뒤 스스로 끝나고 드라이버는 `timeout -s INT -k 15 MAXSEC`로 종료(최대 가동 상한). 시작 실패 시 EXIT trap이 정리 |
| `scripts/pa_snap.py` | 컨테이너 안. 요청 수신 시각(`time.time()`) 이후 **헤더 stamp가 더 큰 첫 color·depth 프레임**만 `color.png`·`depth_mm.npy`·`meta.json`으로 저장. 이미지 변환·PNG 쓰기는 36 s 방식과 같은 `g01_gemini_probe`의 `arr`·`write_png`·`qos`를 그대로 사용. 시작하자마자 옛 파일 삭제, 타임아웃이면 meta(ok=false)만 남기고 종료 코드 3 |
| `scripts/pa_snap_mac.sh` | Mac에서 ssh snap → scp → 크기·요청 id 대조 → `pa_detect.py`. 단계 시각을 Mac 시계로 기록(M1 끝점 = `m_detect_done`). 실패하면 결과 파일을 남기지 않는다 |
| `scripts/pa_detect.py` | 사전 등록 정수 검출기(`evidence/G06/marker_subpix_261117.py`의 `detect(mode=CORNER_REFINE_NONE)` 재사용, 코드를 다시 쓰지 않음) |
| `scripts/pa_eval.py` | 플랜 §3 지표 M1·M1'·M1''·M2a·M2b·M2c·M3·M4 평가. 판정 불가 규칙 포함 |
| `scripts/pa_test_session.py` | 오케스트레이터(약 30분): 기준 사진 A → start → probe → snap 20 → 20분 구동 → probe → stop → 기준 사진 B → stop 뒤 snap 실패 → start/stop 2회(둘째 MAXSEC=45 자동 종료). 모든 질문 직전 입력 버퍼 비우기 |
- **learned-grasp-poc 이식은 하지 않았다.** 플랜은 '이식 후보'였으나 이 프로젝트 36 s 사진과 같은 변환 코드(`g01_gemini_probe`)를 그대로 쓰는 편이 형식 동등성에 더 확실하고 launch 인자도 다르다(점 구름·frame sync 켬). 그래서 이식 대조표는 해당 없음.
