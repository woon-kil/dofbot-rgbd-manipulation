# P-B 도구 구현 중 발견한 설계 결함 이슈보고서 (2026-11-17)

## 현상
P-B(J6 연속 누름) 도구 구현을 advisor가 5라운드 검토하는 동안, 실기기에서 위험으로 이어질 수 있는 설계 결함이 단계별로 나왔다. 모두 하드웨어 실행 전에 잡았다.
1. 블록 있음 시도에서 150 미만 계단이 정체해도 150까지 계속 가서 최대 30 s를 누르는 설계(처음 문서에 "P2i와 같은 방식"이라고 잘못 적음, 실제 P2i는 조기 접촉이면 중단).
2. 시도 직후 질문 "이상이 있었습니까?"에 y=정상으로 처리해 뜻이 뒤집힘.
3. 열기(해제) 쓰기가 폐기돼도 아무도 확인하지 않아 90 s 휴식 내내 블록을 누를 수 있음. 중단 경로(Ctrl-C·종료 신호)의 복귀도 확인 없이 끝남.
4. 재전송 수단으로 `repeat_last`를 쓰려 했으나 이 함수는 복귀가 아니라 **직전 이동(=150)** 을 다시 보낸다.
5. 닫는 방향 복귀 확인 실패 시 손 제거 답 없이 자동 재전송할 뻔함.

## 원인
- P2i 코드를 읽지 않고 기억으로 "같은 방식"이라고 문서에 적었다. 어댑터 함수(`repeat_last`)의 의미를 읽기 전에 설계에 넣었다.
- 정상 경로만 시험하고 쓰기 폐기·중단 경로를 시험 목록에 넣지 않았다.

## 수정
- 조기 정체·블록 미접촉이면 누르지 않고 열고 중단. 총 누름은 150 쓰기부터 T 이하. 질문 문구를 "정상이었습니까?"로.
- 열기 도착 확인(100±3), 실패 시 **새 어댑터로** 같은 쓰기 1회 재전송, 그래도 실패하면 '열기 미확인'으로 모든 후속을 건너뛰고 비상 안내. 중단 경로(`finally`)에도 같은 확인.
- 닫는 방향(시작 179 쪽)은 재전송하지 않고 멈춤. 기록은 `return_sent`와 `returned_to_start`로 분리.
- 가짜 서보 시험 16건(열기 폐기 1·2회, SIGTERM 중 폐기, 닫는 쪽 폐기, 조기 정체, 미접촉, 눌림, E3, None, 상한)을 추가.

## 교훈
- 어댑터 함수는 이름이 아니라 코드로 의미를 확인한다(`repeat_last` = 직전 이동 재전송).
- "이전 시험과 같은 방식"을 문서에 쓰기 전에 그 코드를 연다.
- 새 하드웨어 도구는 쓰기 폐기·중단 신호·복귀 실패 경로를 정상 경로와 같은 비중으로 시험한다.
