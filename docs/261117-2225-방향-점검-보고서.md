## 우려와 근거
1. **문서·사진 판독이 구현·원본과 어긋나는 패턴 반복(3회 연속 점검):** 이번엔 같은 문서 안에서 두 코드의 동작을 섞었다. **권고:** 승인 요청 문서의 동작 서술은 파일:줄 인용으로만 쓴다(이번 §9-3에서 적용).
2. **P-B 조기 접촉 규칙이 새 홀더에서 성립한다는 보장이 없다**(참고용 계산: 회전 2°면 140 계단이 경계). 사용자가 수용했고, 중단 시 규칙을 고치지 않고 기록한다는 사전 등록을 §9-3에 넣었다.
3. 승인 요청 반복 왕복(PB-W): 코드 변경(가)을 고르면 pb5·dry run 3회차가 추가된다. 비용은 낮지만 병목에서 먼 준비가 한 번 더 늘어난다.

## 권고 (우선순위)
1. 사용자: PB-R(`--real` 1회)과 PB-W(가: 카운트다운+벨 추가 / 나: 코드 그대로) 결정.
2. (가) 선택 시 pb5 스냅샷·벨 시험·정정 ①② 후 dry run 3회차 → `--real`. (나) 선택 시 안내문만 보강하고 바로 `--real`.
3. `--real` 결과 보고는 advisor 상위 검토 뒤 제시, 결과 JSON은 `verify_records --add`.
