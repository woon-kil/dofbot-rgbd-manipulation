# 프로젝트 방향 점검 보고서 (2026-11-15 09:02, 11-12~11-15 작업 기준)

질문: 현재 상태에서 프로젝트가 제대로 방향을 잡고 가고 있는가. 방법: 목표·로드맵·SSOT·결정 기록·오차 예산·실기기 실행 기록과 현재 코드를 대조했다(아래 검증 근거). **판단은 근거가 있는 것과 제 의견을 구분해 적는다.** 이 보고서는 의사결정용이며 코드·계획은 바꾸지 않았다.

## 2. 잘 가고 있는 것 (근거 있음)
1. **안전 규율:** 첫 이동 8000 ms, 90°·60 ms/° 상한을 어댑터가 코드로 강제, 매 실행 전 가짜 시험·dry run·advisor 검토·사용자 승인. P1 `--real`은 15이동+복귀 10이동에 재전송 0·중단 0이었다(과거 실행에는 J4 미응답·첫 쓰기 무반응 이슈가 있었고 문서화됐다).
2. **핵심 가설을 실측으로 좁히고 있다:** 마커(25 mm) 근접 관측은 깊이 0.145~0.171 m에서 검출 30/30·재투영 평균 0.35~0.41 px, 왜곡 영향 ≤ 0.7 mm. 폐루프로 개방 루프 오차(FK 대비 5~7 mm)를 흡수하겠다는 설계 방향을 지지하는 데이터다.
3. **자기 교정이 작동한다:** 월드 x 부호 혼용(S4-12), 80° 선례 오인용, M3 통과 오판 같은 오류를 문서화하고 정정했다. 오차 예산(합성 σ ≤ 2.24 mm/축)이 물리 여유(개방 48.5 mm, 블록 29.9 mm)에서 역산된 구조다.
4. **공식 방식과 우리 방식의 차이를 확인했다:** Yahboom 공식 3D 파지는 개방 루프 한 번 이동(태그 중심 깊이 + 고정 보정량)이고 근접 재관측이 없다. 우리 폐루프 근접 관측은 공식의 선례가 아니라 자체 설계이므로 P1 같은 실측이 필요한 것이 맞다.

## 3. 우려와 방향 이탈 징후
### 3-1. SSOT·README가 현실과 다르다 (사실)
- `PROJECT-STATUS.md` 머리말 ‘마지막 갱신 2026-11-12’, 한 줄 상태 ‘설계 초안 + 정적 검증 단계, **로봇 이동·쓰기 호출은 0건**’, 품질 지표 ‘단위 테스트 15개’, README 상태 `NOT_RUN`. 실제는 11-12~11-15에 실기기 실행 기록 60개, 단위 테스트 112개 통과, G04 확증 PASS, P1 완료다. 체크리스트 줄이 한 항목에 수천 자씩 덧붙어 있어(G04·G07 줄) 현재 상태를 읽을 수 없다. 사용자 CLAUDE.md는 PROJECT-STATUS를 단일 진실로 규정한다.
### 3-2. 재현성: 핵심 실행 코드가 git 밖이다 (사실, 사용자 지시 2026-11-12)
- `.gitignore`가 `scripts/`(103개 파일)를 제외해 `git ls-files scripts`는 0개다. 계획 생성기·러너·래퍼·P1 실행 경로가 여기에 있다. 원자료(`evidence/**/raw/`)도 제외다. 실행 사본과 sha256을 촬영 폴더에 남기는 임시 방편은 썼지만 저장소만으로는 시험을 재현할 수 없다. 사용자 결정(제외)이므로 변경은 제안만 한다.
### 3-3. Gate 순서 이탈이 누적됐다 (사실 + 의견)
- 로드맵은 STRICT_LINEAR(선행 PASS 없이 다음 실기기 금지)이고 예외는 G03/G04 순서(ADR-005 결정 2)와 ③ 파일럿(2026-11-14 사용자 수용) 두 가지다. **G02(회독↔FK 검증)는 2026-11-12 조건부 PASS였다**(`docs/261112-2342-G02-판정-결과보고서.md`: holdout 8자세 동결 합격선 6개 모두 통과, 보드 위치 편차 평균 2.41 mm). **이 보고서의 초안은 G02를 미완이라고 적었으나 틀렸다**: SSOT 체크리스트에 G02가 `[ ]`로 남아 있어 잘못 읽은 것이며(그 줄이 낡은 상태, 3-1과 같은 문제), 정정한다. 남는 문제는 G02 합격선이 **절대 높이·J3·J4 이득·영점**을 검증 대상에 넣지 않았다는 점이다. 이후 FK 높이 불일치(약 12~15 mm)가 나타났고 J2 이득·오프셋으로 부분 설명만 됐으며 J3·J4 이득·영점은 식별 불가다. G03(Gemini 보정), G05(교차 검증), G08(듀얼)은 시작 전이다. 필수 구성요소로 정한 Gemini는 지금 ad-hoc 평면 호모그래피로 블록 위치를 확인하는 데만 쓰인다.
- 의견: 예외마다 사유와 기록이 있어 규정 위반은 아니다. 그러나 **안전 게이트가 의존하는 FK의 절대 높이가 G02 판정 밖이었고 불일치가 남은 채로 더 낮은 자세(P1-b2: 모델 높이 30.5 mm, 지금까지 이동한 최저 57.1 mm보다 약 27 mm 아래)로 내려가는 것**이 이번 방향의 가장 큰 위험이다.
### 3-4. 투입이 정밀도 하위 문제에 쏠려 있다 (의견, 근거: 문서·커밋 분포)
- 4일간 커밋 225개(11-12 112, 11-13 95, 11-14 15, 11-15 3), docs 75개 + gates 40개. 11-13~14의 큰 부분이 항 b(카메라→그리퍼 오프셋)·FK 오차·J2 이득 분석이었고, 결과는 ‘직접 측정 불가 → 폐루프로 흡수’로 종결됐다(S4-12·13 승인·실행·정정 반복). 그 결정은 처음부터 가능했던 선택이라 측정 트랙의 한계 비용을 더 일찍 자를 수 있었다.
- P1만 해도 승인 요청 문서가 v1→v2로 다시 쓰였고(HOME→W 분할·J6 98 → 단일 관절·J6 179), 승인 뒤에 ‘K1 기립·오므림’이라는 시작 조건을 알게 되어 변경됐다. **시작 조건·실행 방식 같은 전제를 먼저 확인하는 점검(출발 전 공통 점검)이 늦게 생겼다.**
### 3-5. 최종 목표까지의 거리 (사실)
- 아직 없는 것: 그리퍼를 열고 블록에 접근한 이동, 접촉·파지 감지 수단(SDK에 부하·온도·정지 API 없음), ④ 마무리 보정 알고리즘 구현, 합격 임계값 동결(acceptance-matrix 전부 미동결), G03·G05·G06 본체·G07 P&P, G08. 현재 오프라인에서는 ③ 하강 영역 dry-run만 끝났다.

## 4. 이 길(③ 폐루프 근접 관측 → P1-b2)이 맞는가
**맞는 점:** 컬러 마커 근접 관측이 작동함이 P1로 확인됐고, 공식 방식이 개방 루프라 근접 관측 설계는 우리가 검증해야 한다. 결정 7이 성립하는지(0.13 m 이하)가 ④ 설계의 핵심 미지수다.
**의문 두 가지(의견):**
1. P1-b2는 **이동 상한 30 mm**(c3: 5°급 이동의 모델 일관성 약 1 mm에서 나온 제안)를 만족하려고 더 가까이(0.11~0.13 m) 가려는 것이다. 그런데 30 mm는 자체 제안값이고 M3는 아직 판별 불가다. **0.145~0.15 m에서 관측해 50~100 mm 이동한 뒤의 실제 오차**를 먼저 재면(큰 이동 M3), 더 낮은 자세(미검증 영역)로 내려가지 않고도 ④의 요구를 판단할 수 있다.
2. 최종 목표에 가장 가까운 불확실성(개방 간격·접촉·J6 오므림 상태에서의 파지 준비)은 이 경로의 뒤에 있다. 블록에 대한 **저위험 접근 시험**(그리퍼를 열지 않은 채 손끝 위치만 관측으로 재는 것)은 P1-b2 없이도 가능할지 검토할 가치가 있다.
