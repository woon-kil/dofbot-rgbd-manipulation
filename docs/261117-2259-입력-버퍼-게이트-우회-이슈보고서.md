# 입력 버퍼가 손 보호 게이트를 우회한 이슈 (P-B `--real`, 2026-11-17)

## 현상
P-B `--real`(HEAD `c60a9b0`, 결과 `evidence/records/G01/g01_pb_result-real-261117-224440.json`)에서 대조 시도 뒤 휴식 90 s 동안 사용자가 `y`를 미리 입력했다. 그 입력이 버퍼에 남아, 휴식 뒤 표시된 '블록이 홀더에 고정돼 있고 손·도구가 멀리 있습니까?' 질문(`g01_pb_press_test.py:222~223`)이 표시되자마자 소비됐고 3초 카운트다운과 닫기가 곧장 시작됐다. 사용자가 질문을 읽고 확인한 것이 아니다. 이번 실행에서는 블록 시도의 정체 서명(150에서 146)이 접촉과 일치했고 이상은 없었으나, **이번에 남은 보호는 3초 카운트다운과 벨뿐이었다.**

## 원인
- P-B·배치 사진 도구는 P2i 계열 코드를 바탕으로 했고, 질문 함수가 `g01_5a_gripper_test.ask()`(`input()` 직접 호출, `:46`)이다. 질문 직전 입력 버퍼를 비우지 않는다.
- 같은 프로젝트의 Run 3·4 러너(`g01_p2k_test.py:25~27`)·P2j(`g01_p2j_gripper_test.py:21~25`, P2j-4 승인)·S4-13 러너(`g01_5b4_s42_test.py:24~26`)에는 모든 질문 직전 `termios.tcflush(sys.stdin.fileno(), termios.TCIFLUSH)`가 있다. 이 규칙이 P2i 계열로 옮겨지지 않았다(직전 방향 점검의 '가져온 규칙 불일치' 계열).
- 휴식 중 사용자가 다음 질문을 예측해 미리 답하는 것은 자연스러운 행동이라 사람 쪽 주의만으로는 막을 수 없다.

## 수정 (제안, 미구현 — 코드 변경이라 사용자 승인 필요)
`ask()`를 감싸 모든 질문 직전에 `tcflush`를 호출한다(P2j-4와 같은 방식, 입력이 TTY가 아니면 건너뜀). 대상: P-B(`g01_pb_press_test.py`), 배치 도구(`g01_pb_layout_photo.py`), 이후 들어올림 러너. 가짜 시험: 질문 전에 버퍼에 들어 있던 입력이 소비되지 않는 것(파이프 입력에서는 영향 없음)을 확인. 다음 실기기 도구 사용 전 전제 조건으로 권장한다.

## 교훈
- 손 보호·안전 게이트 질문은 입력 버퍼 비우기가 기본이어야 한다. 한 도구에서 승인된 안전 규칙은 다른 도구로 옮겨졌는지 대조표로 확인한다(상수·규칙 이식 점검).
- 결과 해석에서 '질문에 y로 답했다'는 기록은 그 질문이 실시간으로 답해졌는지(입력 시각·버퍼)까지 확인해야 한다.
- 이번 PB-W (가) 판단(이동 직전 카운트다운+벨)이 결과적으로 마지막 보호 계층이었다.
