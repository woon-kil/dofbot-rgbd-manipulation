# P-A 상시 드라이버 단일 프레임 도구 개발 플랜 (초안, 사용자 승인 전, 로봇 명령 없음, 2026-11-17)

**이 문서는 플랜이다. 사용자 승인 전에는 구현하지 않는다.** 승인 칸과 사전 등록 값은 사용자 승인으로 동결된다. 상위 등급(새 안전 값 E-2'·E-4'의 근거를 만드는 시험): advisor 검토 후 사용자 승인.

## 1. 배경과 목표
- P-B 결과(`docs/gates/G07-PB-J6-연속-누름-시험-승인-요청-문서-초안.md` §10): 150 명령 유지 약 27.8 s까지 검증됨. 들어올림 순서의 누름 합계는 사진 A·B 지연에 크게 좌우된다(`docs/gates/G07-E-2b-들어올림-시험-승인-요청-문서-초안.md` §11-2).
- P-A 0단계(`docs/261117-2322-P-A-0단계-도구-구현-기록.md`, 단일 표본): 현재 사진은 요청→장면 포착 **31.18 s**(`sleep 12` 노출 수렴 워밍업 12 s + 수집 15.42 s + 기동 3.75 s 등)이고 사진은 수집 구간의 **마지막 프레임**이다. 포착 뒤 4.4 s는 정지가 필요 없다.
- **목표(E-1 승인 범위):** 시험 시작 전에 드라이버를 켜고 워밍업을 마친 뒤, 요청 시 **다음 프레임 쌍(color+depth) 1개를 저장해 Mac이 가져오기까지 지연 ≤ 3 s**. 프레임 품질은 36 s 방식과 동등해야 한다. 로봇 명령·Jetson 접속 없음, p620 전용 컨테이너만.

## 2. 설계 (제안)
| 구성 | 내용 |
|---|---|
| `pa_driver.sh start/stop/status` (p620에서 ssh로 실행) | 컨테이너 `dofbot-g01-pa`(원본 `dofbot-g01-camera`와 이름을 달리해 충돌 방지)에서 **원본과 같은 드라이버 인자**(`enable_point_cloud:=false enable_colored_point_cloud:=false enable_publish_extrinsic:=true`, `g01_gemini_check.sh` default 설정)로 launch, 시리얼 대기, 워밍업 `W` s 대기 후 상태 파일 기록. **Gemini 점유 검사는 원본과 동일**(USB 사용 중·다른 컨테이너 점유면 거부). `stop`은 멱등이며 드라이버 INT, 컨테이너 제거, 잔존 확인을 한다 |
| 최대 가동 상한 | 컨테이너가 **30분 뒤 스스로 종료**(`sleep 1800`, 드라이버는 `timeout`), 이후 `status`가 '종료'를 알린다. `start` 실패·Ctrl-C 시 EXIT trap이 정리(원본 cleanup 규칙 유지, 계측·상태 파일 쓰기는 `|| true`) |
| `pa_snap.py`(컨테이너 안) | 구독 노드가 이미 켜져 있는 드라이버에서 **요청 이후 도착한 첫 color+depth 쌍**을 `<이름>/color.png`·`depth_mm.npy`·`meta.json`(요청·프레임 stamp, 저장 시각)으로 저장. 이식 후보: `~/projects/learned-grasp-poc/scripts/gemini_capture.py`의 `wait_pair`(`:172`)·`save_capture`(`:196`) — **이 프로젝트의 사진 형식(`color.png` 720×1280×3, `depth_mm.npy`)과 대조표를 만든 뒤에만 이식한다**(learned-grasp-poc는 다른 launch 인자: 점 구름·frame sync 켬, 이 프로젝트 사진 조건과 다름) |
| `pa_snap_mac.sh <이름>` | Mac에서 ssh로 snap 실행 → scp → 크기 확인, 단계 타임스탬프(원본 규칙: 계측은 제어 흐름을 바꾸지 않음, Mac 구간은 Mac 시계) |
- 안전·한계: 로봇·Jetson 접속 없음. 상시 구동 동안 카메라가 켜져 있다(기존은 사진마다 켜고 끔). 실패하면 기존 `p1_m3_gemini_photo.sh` 36 s 방식으로 돌아간다.

## 3. 시험 (정지 장면, 로봇 명령 없음, p620 입회 1회) 과 사전 등록 지표
**아래 문턱은 측정 전 동결하며(승인 시), 결과를 보고 바꾸지 않는다. 사전 등록 규칙이 실패하면 규칙을 고치지 않고 '불성립'으로 기록한다.** 문턱은 근거와 함께 제안한 값이며 사용자가 바꿀 수 있다(승인 전).
- **시험 순서(같은 세션 앞뒤 기준선, advisor):** ① 기존 도구(`p1_m3_gemini_photo.sh`)로 **기준 사진 1장(36 s 방식)** → ② `pa_driver.sh start`(워밍업 W) → ③ snap 20회(간격 ≥ 5 s) → ④ 20분 연속 구동 확인 → ⑤ `stop` → ⑥ 기존 도구로 **기준 사진 1장** → ⑦ `start/stop` 2회 더(M4). 두 도구는 Gemini 점유 검사 때문에 동시에 못 돌리므로 이 순서로 한다(추가 약 75 s). **같은 장면·같은 세션 조명**에서 P-A 20장을 이 두 기준과 비교한다(조명 변화로 인한 불합격 방지).
- **M2 검출 규칙 = S4' 사전 등록(원문 `docs/gates/G07-S4프라임-관문과-마커-검출-노이즈-제안-초안.md` §2·`:38`·`:50`):** 기존 **정수 검출기 유지**, 잡음 값 **중심 쌍 차 관측 최대 0.32 px(n=4, σ 아님)**, 변 길이 차 ≤ 0.25 px가 사전 등록 값이다. 검출기 구현 파일은 구현 단계에서 파일:줄로 확정한다(미확인).
| 지표 | 방법 | 합격(제안) | 근거 |
|---|---|---|---|
| M1 지연(끝점 = **검출 결과**) | 워밍업 뒤 20회 snap. 요청(Mac `m_start`)→Mac에서 **사진이 파일로 도착해 사전 등록 검출기가 id 7 결과를 낸 시각**을 Mac 시계로 기록(검출기 실행 시간 포함) | **20회 모두 ≤ 3.0 s, E-2' 계산에는 20회 중 최대값을 쓴다**. E-2b §11-2의 '사진 ≤ 3 s'는 **요청→검출 결과**를 뜻한다(S4' go/no-go·E1 판정이 누른 채로 결과를 기다리므로) | `docs/gates/G07-E-2b-…` §2·§4 |
| M1' 프레임 신선도 | `meta.json`에 요청 수신 시각(컨테이너 `time.time()`)과 저장 프레임의 **수신 시각**(같은 시계, 헤더 stamp 아님)을 기록 | **저장 프레임 수신 시각 > 요청 수신 시각, 20/20**(팔이 멈추기 전 프레임으로 판정하지 않기 위함). 참고: pa0 `host_minus_stamp_sec` = color 0.040~0.067 s, depth 0.030~0.052 s(수신−헤더 stamp 차, 단일 표본) | pa0 probe.json |
| M1'' 요청 식별 | `meta.json`에 요청 id를 넣고 Mac에서 일치 확인(P-B 래퍼의 `run_id` 확인과 같은 방식, 이름 재사용으로 옛 파일을 가져오는 것 방지). 30분 상한으로 드라이버가 꺼진 뒤 snap이 오면 **옛 파일 없이 실패**해야 하며, 러너는 이를 '사진 실패'로 보고 **들어올리지 않는다** | 20/20 일치, 종료 후 snap은 실패 | 신규 |
| M2 마커 id 7 | 같은 장면에서 P-A 20장에 위 검출기로 검출, **36 s 기준 2장과 중심·변 길이를 비교** | **20/20 검출, P-A 20장 사이·기준 2장 대비 중심 쌍 최대 차 ≤ 0.32 px, 변 길이 차 ≤ 0.25 px**(S4' 사전 등록 값 그대로) | S4' §2 |
| M3 노출·깊이 | P-A 20장의 평균 밝기·깊이 유효 비율을 **같은 세션 기준 사진 2장의 값과 비교** | P-A 20장이 **기준 2장 범위(앞·뒤 값 사이) ± (밝기 2.0, 깊이 유효 비율 0.02)** 안(모두). 참고 기준선: pa0 워밍업 이후 116.1~116.6, 0.762~0.766(다른 시간대 단일 표본, 합격 기준 아님) | 같은 세션 기준선 |
| M4 안정성 | 20분 연속 구동 + `start/stop` 3회 반복 | 프레임 수신율 ≥ 29 Hz(pa0 30.0), USB 끊김 0, stop 뒤 컨테이너 0개·Gemini 점유 해제 | pa0 `rate` |
| 참고(합격 아님) | 드라이버 시작 직후부터 프레임별 밝기·깊이 유효 비율 시계열 1회 | 워밍업 `W`를 줄일 수 있는지 설계 참고 | `sleep 12` 목적=노출 수렴(`docs/261112-0940-G01-취득-실행플랜.md:22·43`), 12 s 근거는 기록 없음 |
- **snap 방식 기본값:** 요청마다 새 rclpy 노드를 띄우는 방식(상주 노드 없음). pa0에서 잰 `docker exec`+source는 0.34 s이고 rclpy import·init은 재지 않았다(미측정). **이 방식이 M1에서 불합격이면 상주 노드로 바꾸는 것은 문턱 변경이 아니라 새 도구**이며, 같은 지표로 새로 시험하고 사용자 승인을 받는다.
- **결과의 사용:** M1~M4(M1'·M1'' 포함) 전부 합격이면 P-A 성립 → E-2'(합계 ≤ 25 s)·E-4'((나)/(가))를 **측정한 지연의 최대값으로** 확정한다. **M2~M4 중 하나라도 실패하면 문턱을 바꾸지 않고 'P-A 프레임은 등록된 S4'/E1에 쓸 수 없음 = 불성립'으로 기록**하고 E-2b 누름 예산 재논의((가) 40 s 단계 등)로 간다. 이 시험 값은 사진 A·B 지연의 입력일 뿐 안전 한도를 직접 정하지 않는다.
- 사후 분석(사전 등록하지 않은 방법의 재분석)은 '참고용, 결정 근거 아님'으로 표시한다.
