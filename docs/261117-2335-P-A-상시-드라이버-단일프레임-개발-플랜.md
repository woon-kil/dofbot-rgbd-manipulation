# P-A 상시 드라이버 단일 프레임 도구 개발 플랜 (초안, 사용자 승인 전, 로봇 명령 없음, 2026-11-17)

**이 문서는 플랜이다. 사용자 승인 전에는 구현하지 않는다.** 승인 칸과 사전 등록 값은 사용자 승인으로 동결된다. 상위 등급(새 안전 값 E-2'·E-4'의 근거를 만드는 시험): advisor 검토 후 사용자 승인.

## 1. 배경과 목표
- P-B 결과(`docs/gates/G07-PB-J6-연속-누름-시험-승인-요청-문서-초안.md` §10): 150 명령 유지 약 27.8 s까지 검증됨. 들어올림 순서의 누름 합계는 사진 A·B 지연에 크게 좌우된다(`docs/gates/G07-E-2b-들어올림-시험-승인-요청-문서-초안.md` §11-2).
- P-A 0단계(`docs/261117-2322-P-A-0단계-도구-구현-기록.md`, 단일 표본): 현재 사진은 요청→장면 포착 **31.18 s**(`sleep 12` 노출 수렴 워밍업 12 s + 수집 15.42 s + 기동 3.75 s 등)이고 사진은 수집 구간의 **마지막 프레임**이다. 포착 뒤 4.4 s는 정지가 필요 없다.
- **목표(E-1 승인 범위):** 시험 시작 전에 드라이버를 켜고 워밍업을 마친 뒤, 요청 시 **다음 프레임 쌍(color+depth) 1개를 저장해 Mac이 가져오기까지 지연 ≤ 3 s**. 프레임 품질은 36 s 방식과 동등해야 한다. 로봇 명령·Jetson 접속 없음, p620 전용 컨테이너만.

## 3. 시험 (정지 장면, 로봇 명령 없음, p620 입회 1회) 과 사전 등록 지표
**아래 문턱은 측정 전 동결하며(승인 시), 결과를 보고 바꾸지 않는다. 사전 등록 규칙이 실패하면 규칙을 고치지 않고 '불성립'으로 기록한다.** 문턱은 근거와 함께 제안한 값이며 사용자가 바꿀 수 있다(승인 전).
- **시험 순서(같은 세션 앞뒤 기준선, advisor):** ① 기존 도구(`p1_m3_gemini_photo.sh`)로 **기준 사진 1장(36 s 방식)** → ② `pa_driver.sh start`(워밍업 W) → ③ snap 20회(간격 ≥ 5 s) → ④ 20분 연속 구동 확인 → ⑤ `stop` → ⑥ 기존 도구로 **기준 사진 1장** → ⑦ `start/stop` 2회 더(M4). 두 도구는 Gemini 점유 검사 때문에 동시에 못 돌리므로 이 순서로 한다(추가 약 75 s). **같은 장면·같은 세션 조명**에서 P-A 20장을 이 두 기준과 비교한다(조명 변화로 인한 불합격 방지).
- **M2 문턱의 근거(advisor 2~4라운드, 3라운드의 '변 길이 0.25 px 유지' 조언은 철회):** 정수 검출기 = AprilTag 36h11, 기본 `DetectorParameters`(코너 정제 없음)(`scripts/g01_e0g_analyze.py:23~26`의 `detect`, S4' §2 분석 도구 `evidence/G06/marker_subpix_261117.py:8~10`의 `_detector(mode)` 정수 모드). **코드 성질 확인(위치 값은 쓰지 않음):** 프로젝트 `.venv`(cv2 4.14.0)에서 `cornerRefinementMethod=0`(NONE)이고 기존 사진 1장에서 id 7의 꼭짓점 좌표가 **정수값**이었다. 중심=4 꼭짓점 평균이라 **중심 차는 0.25 px 격자(0, 0.25, 0.354, 0.5 …)** 위에만 놓이므로 40~230쌍의 **최대값에 0.32를 적용하면 정지 장면에서도 한 칸 대각선 흔들림 하나(0.354)로 불합격**한다. 변 길이도 E-0G 36 s 방식 정지 반복 차가 0~0.27 px(`docs/gates/G07-E-2-…:97`)라 **36 s 사진끼리도 0.25를 넘는다.** 그래서 M2는 쌍 최대값이 아니라 **하위 규칙이 쓰는 방식**(S4'는 사진 A와 기준 비교 → **편향**, E1은 B와 A 비교 → P-A 연속 쌍의 잡음이 +0.5 px에 닿는지)으로 시험한다. 등록값은 `:50`에 **중심 0.32 px와 yaw(한 번 σ 0.7°·차이 σ ≈ 1.0°)**이고 변 길이 0.75 px(G4, `:25`)·yaw 3.0°(G5, `:26`)는 S4' 관문 값으로 `:50`('S1~S5 권장안 승인, 이 승인으로 S4' 관문·잡음 값이 사전 등록 값으로 쓰인다')의 승인 범위에 든다(승인된 S4' 관문 값). **E1 (ii) 여유 주의:** E-2b §7-2는 변 길이 증가를 '들어올림 약 20 mm에서 약 +0.5 px대(E-0G 기록)'로, E-2 `:97`은 'E-0G 들어올림 30 mm당 +2.3 px'로 적는다(촬영 기하·도출 방식 차이 가능, 확인 필요, 판단은 사용자). **들어올림 시험의 기준 사진이 36 s인지 P-A인지는 E-2b §3 0단계에서 정한다(미정).**
- **M2 검출 규칙 = S4' 사전 등록(원문 `docs/gates/G07-S4프라임-관문과-마커-검출-노이즈-제안-초안.md` §2·`:38`·`:50`):** 기존 **정수 검출기 유지**, 잡음 값 **중심 쌍 차 관측 최대 0.32 px(n=4, σ 아님)**, 변 길이 차 ≤ 0.25 px가 사전 등록 값이다. S4'·Run 3·4 마커 판정에 실제로 쓴 구현 파일은 `scripts/g01_e0g_analyze.py:detect`(aruco 정수 검출)와 일치하는지 구현 단계에서 확정한다(`evidence/G06/p2k_analyze_261117.py`는 aruco를 쓰지 않는 다른 분석, 미확인). 변 길이 문턱 0.25 px는 **E1 (ii) '변 길이 증가 ≥ +0.5 px'(`docs/gates/G07-E-2-파지-들어올림-판정-설계-초안.md:98`)의 판별 여유보다 충분히 작아야 하기 때문**에 0.5로 늘리지 않는다(20 mm 들어올림 신호가 +0.5 px대, E-2b §7-2). 중심 0.354는 중심을 쓰는 규칙(E1 (i) ≥ 8 px, (iii) ≤ 4 px, S4 2 px)에 비해 여유가 크다. 36 s 기준 앞·뒤 두 장의 변 길이 차가 0.25를 넘는 경우는 위 판정 불가 규칙이 거른다.

- **결과의 사용:** M1~M4(M1'·M1'' 포함) 전부 합격이면 P-A 성립 → E-2'(합계 ≤ 25 s)·E-4'((나)/(가))를 **측정한 지연의 최대값으로** 확정한다. **E-2' 사진 항 = M1 최대값 + 결과 전달 경로 지연**이며, S4' go/no-go·E1 결과는 누름 중인 Jetson 러너에 도착해야 쓸 수 있으므로 **전달은 자동으로 하고(사람 전달 금지: 측정되지 않은 사람 반응 시간이 누름 창에 들어간다) 이 지연은 들어올림 러너 dry run에서 따로 잰다**(P-A 시험 범위는 넓히지 않는다). **M2~M4 중 하나라도 실패하면 문턱을 바꾸지 않고 'P-A 프레임은 등록된 S4'/E1에 쓸 수 없음 = 불성립'으로 기록**하고 E-2b 누름 예산 재논의((가) 40 s 단계 등)로 간다. 이 시험 값은 사진 A·B 지연의 입력일 뿐 안전 한도를 직접 정하지 않는다.
- 사후 분석(사전 등록하지 않은 방법의 재분석)은 '참고용, 결정 근거 아님'으로 표시한다.
