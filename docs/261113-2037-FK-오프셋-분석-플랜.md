# FK 오프셋 분석 플랜 v2 (S4-10 후속: H1 기각 뒤 손끝 최저점 위치를 설명하는 모델 찾기)

> v2(advisor 검토 반영): ① S4-10 영상에서 같은 순간의 높이도 읽어 (y, z) 쌍을 확보 ② 같은 프레임에서 손가락 축 각도로 영점 합 판별 ③ y 영점 공통 오차를 자세 간 차이로 분리 ④ 독립 데이터 표 정리. §9 참조.

## 1. 목표
S4-8·S4-9(높이)와 S4-10(y)에서 얻은 **손끝 최저점 실측이 FK(TCP) 예측과 왜 다른지**를, 적은 수의 물리적 매개변수로 설명할 수 있는지 **오프라인으로** 판정한다. 판정이 아니라 "어떤 모델이 데이터와 모순되는가"를 가리는 분석이며, 하드웨어 이동은 없다.

## 2. 현재 상태 (As-Is, 실제 읽은 값)
- 높이(S4-8·S4-9, 눈 읽기 ±2~3 mm, 종이 기준에서 판 윗면 11 mm 뺀 값): 자세 14 → 판 위 54 mm(명령값 FK TCP z 62.5, 차 −8.5), 자세 3 → 51(61.2, −10.2), 자세 0 → 61.5~62(75.3, −13.3~−13.8), 자세 5 → 83.5(101.0, −17.5). 경험식 최저점 ≈ TCP z − 30.6·sin(피치) (피치 sin = TCP 프레임 `R[2,2]` 0.34/0.34/0.42/0.57). 회독 1° 양자화·데드밴드 편향 때문에 **명령값 FK**를 기준으로 한다.
- y(S4-10, 영상 판독, 불확도 약 ±4 mm): 자세 14 / 0 / 5 = 146.7 / 150.2 / 152.0 mm. 명령값 FK TCP y = 140.6 / 153.0 / 151.9 → 차 +6.1 / −2.8 / +0.1. H1(TCP − L·z축 → y 112 / 125.3 / 126.8)은 기각(H1보다 24.9~34.7 mm 사용자 쪽).
- **모순(분석 동기):** 높이는 "TCP에서 −z축 방향으로 약 30.6 mm 아래"(H1 계열)와 맞지만, y는 H1 계열 오프셋(−L·R[1,2])이 거의 없다. 즉 최저점이 TCP 프레임의 한 고정점이라는 가정과 맞지 않는다.
- FK 구현: `scripts/g01_pose_generator.py`의 `fk(sdk)`(URDF 기반, 모델 값 UNVERIFIED, `tcp` = `Gripping_point_Joint`).

## 3. 목표 상태 (To-Be)
후보 모델 각각에 대해 "데이터(높이 4자세 + y 3자세)와의 잔차, 식별 가능성, 과적합 위험"을 표로 제시하고, **모순되는 모델 / 모순되지 않는 모델 / 현재 데이터로 구분 불가**를 구분해 결과보고서에 적는다. 구분 불가이면 이를 가를 다음 측정(예: x 측정, 다른 피치 자세)을 제안한다.

## 4. 접근 방법 (대안 비교)
| 안 | 내용 | 장점 | 단점 |
|---|---|---|---|
| A. 단일 가설 검정 | 단일·소수 매개변수 모델별 최소제곱: ① TCP 프레임 고정점 오프셋(3개), ② J2/J3/J4 영점 오프셋(각 1개씩, 합 3개), ③ 접근축 방향 오프셋 1개(H3) 등을 각각 맞추고 잔차 비교 | 식별 가능성·과적합이 명확, 해석 쉬움 | 모델 외 형상 효과(최저점이 자세마다 달라짐)는 못 잡음 |
| B. 결합 모델 | 고정점 오프셋 + 관절 영점을 한꺼번에 맞춤 | 잔차가 작아짐 | 데이터 7개에 매개변수 6개라 사실상 포화, **근거로 쓸 수 없음** |
| C. 손가락 형상 모델 | 손가락을 선분/직육면체로 두고 "자세별 가장 낮은 점"을 계산 | 최저점이 자세마다 바뀌는 효과를 반영 | 손가락 치수가 없음(URDF 메시 STL로 추정 가능하나 UNVERIFIED), 작업량 큼 |
**권장: A로 시작하고 B는 참고만 한다. A에서 설명 못 하면 C를 후속 플랜으로 둔다.** 관절 오프셋 크기는 물리적으로 작아야 하므로(회독 1° 해상도, J2 영점 보정 이력 ±1~3°) 허용 범위를 사전에 둔다(|δ| ≤ 5°).

## 5. 구현 단계

3. 사전 판정 규칙 고정(코드에 상수로): 잔차 허용 = 높이 ±3 mm, y **자세 간 차이** ±3 mm(공통 y 편향은 별도 성가신 매개변수, 허용 ±4 mm), 손가락 각도 ±3°. 모델이 모든 자세에서 허용 안이고 LOO 예측도 허용 안이면 "모순 없음", 한 자세라도 허용 밖이면 "모순", 허용 안이지만 LOO 예측이 밖이거나 조건수가 크면 "구분 불가".
4. 실행하고 출력 전체를 결과보고서에 코드블록으로 포함. 증거 JSON `evidence/G02/fk_offset_analysis.json`.
5. 결과보고서 `docs/*FK-오프셋-분석-결과보고서.md`, PROJECT-STATUS 갱신, 커밋·푸시.

## 6. 리스크 (Pre-mortem: 이 분석이 실패한다면 이유 3가지)
1. **데이터가 너무 적어 모든 모델이 맞는 것처럼 보인다**(자세 3~4개). → 예방: 단일·소수 매개변수 모델만 근거로 쓰고, 매개변수 수 ≥ 데이터 수 직전인 B는 참고 표기. 조건수와 LOO를 함께 낸다.
2. **측정 정의 차이로 모순처럼 보인다**: 높이는 사람이 눈으로 읽은 값(±2~3 mm, 종이 기준 11 mm 보정), y는 영상 판독(±4 mm, 영점 ±2 mm), "최저점"의 정의가 자세마다 다른 손가락일 수 있다. → 예방: 불확도를 허용 범위로 사전 반영, 최저점이 손가락 형상 효과일 가능성을 결론에 명시(C안 후속).
3. **FK 모델 자체(URDF)가 틀려 어떤 관절 영점으로도 안 맞는다**. → 예방: 관절 오프셋 허용 범위를 사전에 제한하고, 맞지 않으면 "구분 불가/모순"으로 보고하며 억지로 맞추지 않는다(근본 해결 원칙: 케이스별 땜질 금지, 데이터 한 건에 맞추기 금지).

## 9. v2 보강 (advisor 검토 반영)
**9-1. S4-10 영상에서 높이 읽기(같은 순간의 (y, z) 쌍).** 손끝 최저점 행(자세 14/0/5 = 517/434/248, 1080p)과 띠 윗면 행(약 875)과 눈금 9.69 px/mm로 띠 윗면 위 높이를 구하고, **종이 위 띠 높이 h_s**를 더한다. h_s는 사진 환산 약 25~26 mm이고 **사용자에게 자로 1회 재어 달라고 요청**한다(필요한 사용자 입력은 이 숫자 하나). 예비 계산(h_s = 25.5 가정): 영상 기준 판 위 높이 51.4 / 60.0 / 79.2 mm로, 눈으로 읽은 54 / 61.5 / 83.5 mm보다 2.6 / 1.5 / 4.3 mm 낮다. **두 출처 차이가 3 mm를 넘으면(자세 5가 해당 가능) 모델 맞춤 전에 그 차이 자체를 결과로 적고 기준 데이터를 정한다.** 영상이 같은 실행의 (y, z)이므로 이를 1차, 눈 읽기를 교차 확인으로 둔다.
**9-2. 손가락 축 각도.** 같은 프레임에서 손가락 가장자리 선의 기울기를 재 FK 피치(명령값)와 비교한다. 각도는 영점·스케일과 무관해 관절 영점 합(J2+J3+J4) 오류와 툴 형상 문제를 가르는 판별 기준이다. 카메라 롤(약 1°)은 띠 윗면·눈금 세로선으로 보정한다. 두 손가락 끝의 (y, z)를 모두 기록한다(C안 데이터 일부).
**9-3. y 영점 공통 오차.** y = 199 기준은 띠 위치 ±2 mm이고 보드 중심 기록도 227 / 227.5 / 229로 다르다. 1차 근거를 **자세 간 차이**로 둔다(영점 무관). 측정 14→0 +3.5, 0→5 +1.8; FK +12.4, −1.1. 공통 y 편향은 관절 오프셋이 흡수하지 않도록 별도 성가신 매개변수 1개(허용 ±4 mm)로 둔다.
**9-4. 데이터 독립성 표**(분석 시 확정): 독립 관측 = 자세 14·0·5의 영상 (y, z, 손가락 각도) 3세트 + 자세 3의 눈 읽기 z 1개 + 자세 14·0·5의 눈 읽기 z 3개(영상 z와 같은 자세라 교차 확인용, 독립 데이터로 세지 않음). 매개변수 수는 독립 관측 수보다 작게 유지한다.
**9-5.** 명령값과 정착 각도의 ±1° 차이(데드밴드, R27)는 상수 영점이 아니므로 맞춤 매개변수로 넣지 않고 **민감도 행**(±1°당 y·z 변화)으로만 낸다.
