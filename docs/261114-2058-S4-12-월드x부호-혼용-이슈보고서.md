# S4-12 월드 x 부호 혼용 이슈보고서 (2026-11-14)

## 현상
- S4-12(대각선 폰)의 카메라 프레임 점 x는 −17.5 mm였고 "J1 변경 304 강체 일관성 20 mm 불일치"가 있었다. S4-13(측면 폰 보드 정합) 점은 같은 자세에서 카메라 x **+46.2**다. 같은 점인데 약 64 mm 차이.
- S4-13 §18 월드 점(x −31.4)을 FK 체인으로 옮기면 x +35.2다. 월드 점에서 FK TCP를 빼면 304가 −52.7 mm로 튄다.

```
(§18 월드 점 − FK TCP, 부호 혼용)  300 [-33.3, -3.0, 10.5]  ...  304 [-52.7, -5.4, 10.1]
(FK 체인으로 옮긴 점 − FK TCP)     300 [ 33.3, -6.7, 11.9]  ...  304 [ 32.4, -9.0, 11.6]
(S4-12 스크립트, 점 x 부호만 뒤집음) 300 [35.3, -9.0, -7.0] ... 304 [33.3, -8.9, -7.0]  (옛 부호: 304가 20 mm 어긋남)
```

## 원인
- 프로젝트 월드(x가 사용자 오른쪽, y 사용자 쪽, z 위)는 **왼손계**이고 FK(URDF) 월드는 오른손계로 **x가 반대**다. §18 변환식은 월드 = (bx−36, by+199, 0.8−bz)(행렬식 −1).
- S4-12 계산 스크립트(`s412_step2_x32.py`)는 점 x(프로젝트 규약 −32.5…−41.4)를 FK 월드용 보드→월드 회전(`diag(−1,1,−1)`, 행렬식 +1)에 그대로 넣었다 → 점이 반대 손가락 쪽 보드 좌표 bx≈68로 올라갔다(옳은 값 bx≈4.6). x 거울상은 J2 회전(x축 회전)과 교환되어 300~303은 재현되지만 J1(z축 회전) 자세 304에서는 어긋난다.
- 부호만 뒤집은 재실행: 카메라 x 45.5~47.5(§18 45.3~47.4와 일치), 304 점−TCP 33.3 대 300~303 34.4~35.3.

## 수정
- 항 b 계산은 부호에 의존하지 않는 DaBai 프레임 점(§18)과 FK 체인 값만 사용(`docs/261114-2055-S4-13-항b-점-TCP-계산-결과보고서.md`).
- §18에 "월드 점표는 왼손 보고 프레임, FK 월드와 x 반대" 주석, S4-12 보고서에 정정 주석, 인계 문서 "다시 쓰지 말 것"에 항목 추가.
- A안(비접촉 추정, 점 x −6 가정)도 같은 혼용이 있었다. y·z 차이(−10, −5 mm)와 "높이 14 mm 불일치"는 재확인이 필요하다(보드 z 기준 0.8 대 −10.2 mm도 다름). 접근 단계에는 영향이 작다는 기존 판단은 유지하나 재검증 항목으로 남긴다.

## 교훈
1. 좌표계를 건너는 값에는 반드시 **행렬식 부호와 축 방향 정의**를 같이 적는다(왼손/오른손, x 방향).
2. 서로 다른 프레임의 값을 빼기 전에, 같은 점을 두 경로로 옮긴 값이 일치하는지(예: 월드 x −31 대 FK 체인 +35) 한 번 확인한다.
3. "J2만 바뀌는 자세는 재현되는데 J1 자세만 어긋난다"는 거울상 부호 오류의 전형 신호다. 원인으로 "강체 불일치"를 쓰기 전에 부호를 의심한다.
4. 사용자 질문이나 이상 수치는 먼저 서로 다른 보고서의 같은 양을 대조한다(여기서는 카메라 x −17.5 대 +46.2).
