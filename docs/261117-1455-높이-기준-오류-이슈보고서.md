# 높이 기준 오류(FK z 대 종이 위 높이) 이슈보고서 — 2026-11-17

## 현상
Run 2·3 설계가 닫힘 모델 캡 끝 높이(예: Run 2 21 mm, Run 3 9.9 mm)를 FK z로 계산해 놓고 "종이 위"로 불렀다. 승인 문서의 닫기 직전 높이 관문(7 mm)도 FK 기준으로 구현돼 의미가 달랐다. 간격 스크립트는 블록 상자 중심 z를 FK 15 mm로 둬 블록이 11 mm 높았고, "최저 점 높이" 열도 FK z를 '종이 위'로 표기했다.

## 원인
종이 위 높이 = FK z + 11 mm(`TABLE_Z` = −11 mm)인데, 새 시험 설계 때 이 기준 병기 규칙을 적용하지 않았다. 기존 메모리 `feedback_state_basis_and_run_generator_before_approval.md`에 규칙이 있었다. advisor 검토가 dry run 안내 직전에 잡았다.

## 수정
D0 세 자세에서 FK 계산값과 보고서 종이 기준 값의 차(11.1~11.2 mm)를 확인하고, 자세를 A (J2 69, J3 12, J4 32)로, 관문을 종이 위 7 mm로 정정했다. 사용자가 새 안전 값 N1(J2 창 하한 66)·N2(전이 하한 32)를 승인했다. 간격 스크립트의 블록 z와 열 이름을 고치고 dz −6 변형을 추가했다. Run 2 보고서·PROJECT-STATUS에 정정을 남겼다(§17, 커밋 b972ab7, ae220f5).

## 교훈
- 높이 숫자는 항상 **'FK z / 종이 위'를 병기**한다. 승인 요청 전에 계산 스크립트 출력의 열 이름과 기준을 읽는다.
- 이 사례는 규칙이 있었는데 적용하지 못한 사례다(메모리에 덧붙임).
