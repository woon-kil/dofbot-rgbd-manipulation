## 결론
1. **공식 3D 파지는 개방 루프 한 번 이동이다.** 고정 "인식 자세"에서 AprilTag(`tag36h11`, 목재 블록 윗면 30×30×30 또는 40×40×40 mm)를 컬러 영상으로 검출 → 태그 중심 픽셀의 **깊이 값**(0이면 무효)을 읽어 카메라 3D 점 → 고정 `EndToCamMat`로 베이스 좌표 → 고정 보정량(`x_offset`, `y_offset`, `z_offset`)을 더함 → IK 서비스 → `Arm_serial_servo_write6` 한 번으로 파지 자세로 이동(대기 3.5 s) → 집게 닫기. **근접 재관측과 보정 이동이 없다.**
2. **태그 자세(PnP)를 쓰지 않는다.** `at_detector.detect(gray, False, None, 0.025)`의 `estimate_tag_pose=False`, 카메라 파라미터 없음. 위치는 깊이 센서, 회전은 태그 모서리 방향각으로 J5만 정한다. 즉 컬러 영상만으로 3D 위치를 얻는 경로가 공식에는 없다.
3. **깊이 센서에 의존하므로 가까이서는 못 쓴다.** 조건은 "깊이 ≠ 0이고 베이스에서 태그까지 거리 0.18 m 초과 0.30 m 미만". 카메라 최소 거리 규정은 코드에 없고, DaBai DCW2 표는 작동 거리 0.15~3 m다(`data/refs/dabai-dcw2-spec-table.md`).
4. **추적 단계는 픽셀 서보다.** 태그 중심이 영상 중심(320, 240)과 ±2 px 안에 50프레임 연속 머물러야 파지를 시작한다(`apriltag_follow`).
5. **2D 색 블록 파지는 지도(맵) 고정 위치**다. HSV로 색만 판별하고 팔은 지도 위 미리 정한 자세로 간다(`Color_Grab`).
6. **고정 보정량과 경험식이 코드에 박혀 있다.** `pose_T[0]−0.01`, `tar_z = pose_T[2] + (r − 0.181)·0.2`("실제에 맞춰 조금 조정"), J4는 90 상한, J5 = 90, J6 = 30, 초기 자세 `[90, 120, 0, 0, 90, 90]`.

```
EndToCamMat = [[1, 0, 0, 0], [0, 7.96e-4, 0.99999968, -0.099], [0, -0.99999968, 7.96e-4, 0.049], [0, 0, 0, 1]]   # 공식 코드의 카메라→끝 변환(CAD 값)
camera_info_K = [477.574, 0, 319.382, 0, 477.557, 238.641, 0, 0, 1]   # 공식 코드의 깊이 카메라 내부 파라미터
우리 측정(S4-13) 카메라→캡 끝면 가운데: (10.8, 52.8, 95.9) mm ±2, URDF만: (0.2, 49.3, 98.8) mm
```
- 공식 `EndToCamMat` 이동 (0, 0.049, 0.099) m는 우리가 계산한 URDF만 예측(0.2, 49.3, 98.8 mm)과 **같은 크기**다(두 값 모두 CAD). 우리가 측정한 실제는 x가 약 +10.6 mm 다르다. 공식은 이런 차이를 고정 오프셋과 경험식으로 흡수하고, 우리는 측정으로 분리했다.

## 우리 ③ 결정에 주는 함의
- **공식 방식은 우리 문제(마무리 σ ≤ 2.24 mm/축)의 선례가 아니다.** 블록 30~40 mm에 개방 루프 오차 수 mm~cm를 허용한다. 근접 재관측 폐루프를 쓰지 않으므로 "깊이 최소 거리 0.15 대 0.2 m"를 부딪힐 일이 없었다.
- **권장 1(컬러 마커, 깊이 최소 거리 없음)은 유지된다.** 공식에는 근접(0.1 m대) 관측 사례가 없어서 이 방식이 되는지는 여전히 P1 실측이 필요하다. 공식이 쓰는 마커는 `tag36h11` AprilTag와 목재 블록(30·40 mm)이다. 우리가 PnP를 쓰려면 (마커 크기 + 보정된 K)가 필요하다.
- **블록 규격:** 공식 예제 블록은 30×30×30 mm(분류), 40×40×40 mm(추적 파지)다. 우리 예산 근거 블록(폭 30 × 길이 60 mm)과 다르지만 같은 크기 계열이다. 높이 50 mm 권장은 공식 예제에 없는 우리 FK 여유 계산 결과다.
- **작동 반경:** 공식은 베이스에서 0.18~0.30 m에서 잡는다. 우리 격자 반경 110~190 mm(접근 기울기 ≤ 15°)는 그보다 안쪽이고 더 수직이다. 공식은 J4 ≤ 90 외 접근 기울기 제한이 없다.
- 공식 코드의 `x_offset`·`y_offset`·`z_offset`는 로봇별 보정 파일(`offset_config`)에서 온다. 값과 보정 절차는 "Calibration offset" 단원(12502)에 있을 수 있으나 본문을 추출하지 못해 확인하지 못했다.

## 추가 판독 결과 (이전에 읽지 못했던 단원)
```
공식 인식 자세 TCP (base 프레임): (-0.006, 0.116, 0.091) m, roll -60°   # 12554 CurEndPos
공식 보정 태그 위치 (base 프레임): (0, 0.181, -0.01) m                    # 12502
TCP→보정 태그 거리: sqrt(0.006² + 0.065² + 0.101²) = 0.120 m
공식 보정 결과 파일 offset_value.yaml 예시: x_offset 0.0, y_offset 0.01164, z_offset -0.0092 m
```
1. **공식 보정(Calibration offset)** = 지도 위 보정 태그의 알려진 base 좌표와 인식 자세에서 카메라가 낸 좌표의 차이를 `offset_value.yaml`에 저장해 이후 파지 목표에 더한다. 서보 편차 때문에 "낙하점이 앞뒤로 조금 어긋나서"라고 설명한다. 보정은 **한 점·한 자세**이고 자세 의존 오차나 이득은 다루지 않는다. 예시 z 오프셋 −9.2 mm와 y +11.6 mm는 우리가 FK와 PnP 사이에서 본 높이 오프셋(−10.4~−15 mm)과 같은 크기다.
2. **공식 관측→파지 거리:** 인식 자세에서 TCP가 보정 태그까지 약 120 mm 떨어져 있고 한 번에 이동한다. 우리 G06 계산(깊이 최소 0.2 m, 이동 약 105 mm, `docs/261114-2320-G06-부분-dry-run-결과보고서.md`)과 **독립적으로 같은 크기**다. 공식 설계도 "멀리서 보고 한 번에 점프"이며 근접 재관측이 아니다.
3. **색 블록 추적 파지(12564):** HSV로 색을 정하고 중심이 영상 중심에서 ±10 px 이내(AprilTag는 ±2 px)로 50프레임 정지하면 깊이(≠0)로 파지한다. 초기 자세 `[90, 150, 12, 20, 90, 30]`, 40×40×40 mm 블록. **KCF(12565)** 는 흐름도 이미지만 있었고 같은 로직(중심 ±10 px, 50회 정지, 깊이 999 아님)이다. 코드는 스크린샷이 아니라 흐름도였다.
4. **높이 이상 분류(12554):** 30×30×30 대 30×30×60 mm 블록을 깊이로 계산한 높이로 구분한다(`compute_heigh`, 같은 `EndToCamMat`).
5. **지도(12505):** 500×520 mm 인쇄 지도에 베이스 판 자리, 십자 목표, 쓰레기 분류 구역 4곳이 있다(그림 확인). 로봇은 지도의 고정 자리에 놓여 보정 태그·목표 위치가 지도 좌표로 정해진다.
